# 공개 배포 가부 검토 (2026-08-16)

**결론: 아직 공개하면 안 된다. 다만 막고 있는 것은 기술이 아니다.**

기술 쪽 안전장치(L1~L7)는 **하나를 빼고 전부 살아 있다.** 남은 것은
① 5분이면 되는 설정 하나, ② 아직 만들지 않은 문서 두 개, ③ **내가 답할 수 없는 법률 판단 다섯 개**다.

> ⚠**이 문서는 법률 자문이 아니다.** CLAUDE.md §2-5와 같은 전제 위에 있다 —
> 공개 전환을 결정하는 시점에는 **일본 변호사 확인을 거친다.**

## 1. 4층 점검 (CLAUDE.md §2-5)

| 층 | 지금 상태 | 판정 |
|---|---|---|
| **1. 사실 자체** | 개별 기록은 저작물이 아니다 | 문제 없음 |
| **2. 편집물로서의 DB** | 원본 표 레이아웃을 재현하지 않는다. 원시 기록을 받아 우리 스키마로 재구성하고, 화면의 주역은 **우리가 계산한 값**(wOBA·wRC+·FIP·SRC·SRP·RE24) | 낮음 |
| **3. 일반 불법행위** | 위험 인자 4개 중 **영리목적 ✕ · 신선도 이용 ✕ · 데드카피 ✕ · 경합 △**. 앞의 셋은 성립하지 않는다 | **미해결** — §3 참조 |
| **4. 계약·규정** | npb.jp 푸터의 二次利用 금지, NPB 규정 제4조1항(2) 리얼타임 배신 금지. **라이브 취득 0건**으로 4층은 정면 회피 | 낮음 |

## 2. 안전장치 L1~L7 — 실측 상태

| # | 규칙 | 실측 | 판정 |
|---|---|---|---|
| **L1** | 1req/2~5초 · 동시 1 · 식별 가능한 UA + 연락처 | 기본 간격 **3,000ms**, 동시 1커넥션. UA = `bb-app-archiver/0.1 (personal, non-commercial; <연락처>)`. ⚠**연락처가 없으면 예외를 던져 수집이 시작되지 않는다** — 규칙이 코드로 강제돼 있다 | ✅ |
| **L2** | 원본 표 레이아웃 미재현 | 이닝별 스코어보드조차 재현하지 않는다(가진 것이 R·H·E뿐이라는 사실에 화면을 맞췄다) | ✅ |
| **L3** | 전 화면 출처 명기 + 원본 링크 | 푸터에 `出典：日本野球機構（NPB）公式サイト npb.jp` — **3,213장 전부** | ✅ |
| **L4** | 삭제·정정 요청 창구 | ⚠**미설정.** `BB_CONTACT`가 비어 있고, 화면이 스스로 「連絡先が未設定です（公開前に設定してください）」라고 말하고 있다 | ❌ **블로커** |
| **L5** | 공개된 직업활동 성적만 | DB에 생년월일 695명·체격 695명. **화면에는 생년(연도)과 체격만 나가고 생년월일 전체는 나가지 않는다**(실측). 비공개 정보는 수집하지 않는다 | ✅ (단 §3-1 참조) |
| **L6** | 원시 아카이브 내부 보관, 외부는 파생값 | 원시 HTML은 GitHub 릴리스(비공개 자산)에만. `dist/`에 원시 아카이브 0건 | ✅ |
| **L7** | 조건부 요청·캐시 우선 | `If-None-Match` / `If-Modified-Since` 전송, 304를 `unchanged`로 처리 | ✅ |

**추가 실측**
- 선수 사진·구단 로고·엠블럼 **0건**, `<img>` 태그 **0건**
- 외부 도메인 참조 **0건**(폰트·CDN·분석 도구 전부 없음)
- 라이브 취득 **0건**
- 현재 `<meta name="robots" content="noindex, nofollow">` — 검색엔진에 올라가지 않는다

## 3. 공개 전 반드시 해결해야 하는 것

### 3-1. 내가 지금 할 수 있는 것 (블로커)

| # | 항목 | 왜 | 규모 |
|---|---|---|---|
| **B1** | **`BB_CONTACT` 설정**(L4) | 삭제·정정 요청 창구 없이 공개하는 것은 §2-5의 최소 대응을 어기는 것이다. 화면이 이미 그 사실을 광고하고 있다 | 5분(시크릿 등록) |
| **B2** | **이용목적 공표(프라이버시 폴리시) 페이지** | §7-C #1의 최소 대응 3종 중 하나. 「무엇을·왜·어디서 모으고 어떻게 쓰는가」와 본인 문의 경로. **지금 이 페이지 자체가 없다** | 반나절 |
| **B3** | **이용약관/면책 페이지** | 수치는 우리 재계산이고 공식 기록과 다를 수 있다는 것, 비영리·비공식이라는 것 | 반나절 |
| **B4** | **`noindex` 유지 여부 결정** | 떼는 순간 3층의 「경합」 인자가 올라간다. **떼지 않고 공개**(URL을 아는 사람만)도 선택지다 | 판단 |
| **B5** | **한국어 개발 주석 제거 검토** | 공개 HTML에 내부 주석 **9,646개 · 1.59MB**가 실린다. 미공개 정보는 없지만 설계 의도가 전부 노출되고, 일본어 대상 서비스에 한국어가 섞인다 | 반나절 |

⚠**B5는 딜레마다.** 이 프로젝트의 주석은 「왜 이렇게 만들었는가」를 담은 자산이고, 소스에서 지울 이유는 없다.
**빌드 시점에만 벗기는 것**(렌더 후 `<!-- -->` 제거)이 맞는 답이다 — 소스는 그대로 두고 산출물만 깨끗해진다.

## 4. 권고

### 4-1. 지금 (S1 유지)

**공개하지 않는다.** Cloudflare Access + 허용목록을 유지한다. 실측으로 프로덕션 URL과
배포별 해시 URL 양쪽이 302 → Access 로그인으로 막혀 있음을 확인했다.

이 단계의 목적은 「보여주기」가 아니라 **아카이브 축적**이다 — playbyplay는 2025년분부터만 존재하고,
롤오프 여부가 미결이라 **지금 모아 두는 것 자체가 소급 불가능한 자산**이다.

### 4-2. 공개 전환 게이트 (전부 만족해야 함)

1. B1~B5 완료
2. **일본 변호사 확인** — L-1(PPC)·L-3(경합)·L-4(준거법) 3건을 안건으로
3. 운영 주체 표시 확정(개인정보처리방침·약관의 사업자 필드)
4. **「우리가 계산한 것」의 비중**이 충분히 커졌는지 재확인 — 지금도 이미 크지만(wOBA·wRC+·FIP·SRC·SRP·RE24가 전부 자체 산출), 화면 구성 기준으로 한 번 더 센다

### 4-3. 절대 하지 말 것

- **수익화·광고** — 붙는 순간 3층의 영리목적 인자가 서고, 翼/YOL 양쪽 판단요소가 강화된다(§2-5 S3)
- **라이브 취득** — 3층(신선도 이용)과 4층(규정)에 정면으로 걸린다. 지금의 「유저가 고르는」 설계를 유지한다
- **수집 간격 단축** — L1은 정량 기준이 없는 영역에서의 안전측 설계다. 빠르게 할 이유가 생기면 그때가 위험하다

## 5. 한 줄 요약

**기술은 준비됐다. 문서 세 개와 변호사 확인 하나가 남았다.**
그리고 그 변호사 확인은 「해도 되는가」가 아니라 **「어느 형태까지 해도 되는가」**를 묻는 자리다.
