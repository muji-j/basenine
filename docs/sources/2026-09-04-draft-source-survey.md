## 1. URL 구조 (실측)

`https://npb.jp/draft/` → **302** → `http://draft.npb.jp/draft/` → **301** → `https://draft.npb.jp/draft/`
→ **meta refresh** → `./2026/`. **별도 서브도메인이고 CDN(`Via: JSTCDN`) 뒤에 있다.**

```
https://draft.npb.jp/draft/backnumber.html           연도 색인 (2001~2026 · 26건 · 결번 0)
https://draft.npb.jp/draft/{YYYY}/                   연도 톱
```

## 2. 「이미 가진 것」이 왜 안 되는가

`packages/store/migrations/011-player-draft.sql` 의 `player.draft TEXT` 는 `2000年ドラフト5位` **원문**이다.

- **담는 것**: 연도 + 순위 + `育成` 여부. **안 담는 것**: 지명 구단 · 경합 · 추첨 · 전체 순번 → 요구 ①~④ 중 **0개**.
- ⚠**제약이 실측으로 더 구체화됐다.** 2025년 **佐々木麟太郎**(소프트뱅크 1위·추첨 당첨)·**石川ケニー**(오릭스 6위)가
  **둘 다 입단 거부**하고 MLB로 갔다. → **「소프트뱅크가 1위 추첨에서 이겼다」는 사실이 우리 `player` 표에
  들어갈 자리가 영원히 없다.**
- **「추첨에서 진 구단」은 원리적으로 선수 단위로 표현 불가**다 — 진 구단은 그 선수와 아무 기록도 안 남긴다.
- → 드래프트는 `player` 의 속성이 아니라 **독립 이벤트 표**여야 한다. **소스 문제가 아니라 모델링 결론이다.**

### 3-1. npb.jp `draftlist_{team}.html` — **조건부 채용 · 확신도: 확정**

- **제공**: 구단별 순위별 **선수명 / 포지션 / 소속**. `新人選手選択会議` 와 `育成選手選択会議` 가 **별도 `<h4>` 섹션**.

- **포맷**: 정적 HTML `<table>`. **JSON API·AJAX 0건**(스크립트 참조 실측). 인증 불필요.
- **갱신**: **연 1회 이벤트.** 2026 페이지는 개최 2개월 전 현재 `開催要項`만 있고 `draftlist_*` 는 **당일** 생긴다.
- **과거 범위**: `backnumber.html` 이 **2001~2026 · 26년 · 결번 0**.
  ⚠**실제로 받아 파싱 확인한 것은 8/26**(2001·2006·2013·2019·2022·2023·2024·2025). 나머지 18개 연도는 안 받았다.
- **robots.txt**: `https://draft.npb.jp/robots.txt` → **302 → `http://npb.jp/robots.txt` → 404**.
  ⚠**404 는 「허용」이 아니라 「지시 없음」이다.**
- **이용약관**: **npb.jp 에 별도 약관 페이지가 없다.** 푸터 링크 8개에 약관이 없다. 4층 근거는 푸터 한 줄:
  > `掲載の情報、画像、映像等の二次利用および無断転載を固く禁じます。`
- **§2-5 4층 판정**: 1층=사실 / 2층=**원표 구성을 재현하지 않는다**(L2) / 3층=비영리·비경합·연 1회·자체 재구성 /
  4층=**재배포 형태를 취하지 않는다**. 라이브 규정은 무관(연 1회 확정 데이터).
- **안정성**: 연대별 마크업 상이(§4). 비공식 API 없음. 차단 정황 없음.
  ⚠**`ETag`·`Last-Modified` 가 저장한 응답 9건 중 0건** → **L7(조건부 요청)이 이 호스트에서 성립하지 않는다.**
- **신뢰 등급**: **공식(NPB)**.

  ⑵ **불변식을 시험으로 강제**(「색 그룹마다 굵은 셀 정확히 1개」·「`1巡目k` 낙첨 수 = 다음 행 재입찰 수」) —
  **위반 시 빈 값이 아니라 실패**(M7) ⑶ **표를 재현하지 않는다**(L2·SA)
  ⑷ 출처·라이선스·`最終更新` 을 레코드에 남긴다(M4·BY).
- ⚠**4/62만 봤다. 「1965년부터 된다」고 쓰지 마라 — 「기사가 62년치 있다」까지만 참이다.**

### 3-8. 12구단 공식 사이트 — **미검증**

robots.txt 실측(기존 표본 재사용 · 신규 요청 0): 12구단 중 **200=3**(DeNA·広島·ヤクルト) · **404=8** · **403=1**(読売).
**드래프트 페이지는 하나도 받지 않았다 → 「쓸 수 있다」고 쓰지 않는다.**
⚠**받아 봐도 이 구멍은 못 메운다** — 구단 사이트는 자기 지명만 말하고 **낙첨한 구단은 그 선수와 아무 기록도
안 남긴다.** 경합은 12구단을 가로지르는 사실이다.

### 3-9. 스포츠 언론 — **미검증**

1건도 받지 않았다. ⚠**「약관상 안 될 것이다」도 쓰지 않는다.** 다만 후보로 올리지 않는다 —
§2-5 3층 인자(신선도 이용·데드카피·경합)가 언론 표를 그대로 옮길 때 정면으로 선다.

### 3-10. Yahoo!/スポーツナビ 계열 — **불가(기존 판정 원용) · 확정**

LINE ヤフー 이용규약 14가 「제공 목적을 넘는 이용」을 정면 금지하고 **영리 요건이 없다**
(`docs/sources/2026-08-20-blocked-metrics-source-survey.md`).

## 6. 정정(revision) — 실재하고, 감지 수단이 하나뿐이다

- **드래프트 결과는 사후에 정정된 적이 있다.** 2005 高校生ドラフト에서 추첨 결과가 잘못 발표돼
  교섭권 획득 구단이 정정됐다(**辻内崇伸**: 발표 オリックス → 정정 **巨人** / **陽仲壽**: 발표 ソフトバンク →
  정정 **日本ハム**). 근거: ja.wikipedia 2005 기사 `交渉権訂正` 절.
- **npb.jp 는 정정을 표시하지 않는다** — 최종 상태만 싣는다. `ETag`·`Last-Modified` 가 **0/9** 라
  **바이트 비교 말고 판을 알 방법이 없다.**
- → **M4 대응**: 드래프트 표는 **`source`·`fetched_at`·`revision`(내용 해시)** 을 **자체 컬럼**으로 가져야 한다.
  경기와 달리 **부모를 타고 답할 상대가 없다.**
- **입단 거부는 사후 사실이다** — 2025 佐々木·石川은 **2026년 7월**에 확정됐다.
  **「지명」과 「입단」은 다른 사실이고 시점도 다르다.** 같은 표에 섞지 마라.

## 7. 갱신 주기 — 경기 수집과 층이 완전히 다르다

```
연 1회 이벤트. 2026년은 10월 22일(목).
 T-2개월  /draft/2026/ 에 開催要項+뉴스만 (2026-09-04 현재 이 상태 · 실측)
 T-1개월  information/schedule 이 생긴다 (⚠추정 — 2025 뉴스 날짜 역산 · 미검증)
 T+0      draftlist_{team}.html 12장
 T+수일~  ja.wikipedia 가 채워지고 이후 몇 달~1년 편집 계속
 이후     사실상 동결
```

- **권고 취득**: `backnumber.html` 1장 → 새 연도 감지 → 그 연도만 **연 1회 + 개최 후 7일간 1일 1회**.
  한 시즌 = `index` 1 + `schedule` 1 + `draftlist` 12 = **14장**.
  2005~2026 소급 = **22 × 14 = 308장** = L1(3초)로 **약 15분**.
  ⚠경기 수집(31,220요청·약 34시간)과 비교하면 무시 가능하다.
- ⚠**하루 1회 배치에 얹지 마라.** 1년 중 대부분은 안 바뀌는 페이지를 다시 받는 일이고,
  `ETag` 가 없어 조건부 요청으로 줄일 수도 없다.

## 8. 자동이 안 되는 부분 (§0 제약3)

**2024 이후 시즌의 경합·추첨·외れ1位** — 이것만 npb.jp 자동 취득 경로가 없다.

| 안 | 비용 | 리스크 |
|---|---|---|
| A. 수동 입력 | 한 시즌 **30~60분**. 1순위 그리드 **12구단 × 최대 3회차 = 최대 36칸** + 당락 플래그 | 오타. **분모가 작아 눈으로 검산된다** |
| **B. ja.wikipedia 자동 파싱** | 초기 **2~3일** + 매년 재확인 | §3-7의 4가지. **범례 없는 CSS를 계약처럼 믿는 것이 본체 리스크** |
| C. 안 만든다 | 0 | 요구 ②③이 최신 시즌에서 빈다 |

**조사자 권고는 A**였으나 **2026-09-04 사용자 결정으로 B를 채택**한다.
⚠**그 대신 「불일치가 안 일어나게 규칙을 확실히 정립」이 조건으로 붙었다**(사용자 요구).
→ **2005~2023 의 19시즌에서 npb.jp 문장과 wikipedia 색을 대조**해 파싱 규칙을 검증하고,
그 결과를 근거로 2024~ 에 적용한다. **정본은 npb.jp(공식), wikipedia 는 보조**(§2-4 신뢰 등급).

⚠**화면 문구를 구별하라**(M12·M11): 2024 이후 = **「NPB가 공표하지 않는다」** /
2001~2005 = **「확인하지 않았다」**. **「데이터가 없습니다」로 뭉뚱그리지 마라.**

## 9. 요청 로그와 이 조사의 한계

**9-A. 요청 수 (L1)** — `npb.jp`+`draft.npb.jp` **29**(리다이렉트 1홉 포함) / `ja.wikipedia.org` **8** / **합계 37**.

- **UA**: `bb-app-archiver/0.1 (personal, non-commercial; <연락처>)` — 저장소 `buildUserAgent()` 형식과 동일.
- **동시성 1** — 순차만. 병렬 0건.
- **간격**: `--rate 12/m`(1req/5초). **응답 `Date` 실측(9건) 최소 간격 5초**, 단 **2건은 같은 초**(리다이렉트 추종 1홉).
  ⚠**「1req/5초를 100% 지켰다」고 쓰지 마라 — 리다이렉트 홉은 간격 밖이다.**
- **L7**: 걸지 않았다. 첫 취득이라 이전 메타가 없었고, npb.jp가 `ETag`·`Last-Modified` 를 **0/9** 로 안 준다.

**9-B. ⚠이 조사가 저지른 것**

- **`ja.wikipedia.org/w/api.php` 에 1건 요청했다**(robots `Disallow: /w/`). robots와 **같은 배치**로 보내
  결과를 읽기 전에 나갔다. → **robots는 단독으로 먼저 받고, 읽은 뒤에 다음 요청을 짜라.** 이후 요청은 전부 `/wiki/`.
- **제목을 틀려 404를 1건 냈다.** 검색으로 확인한 뒤 쳤어야 했다.

**9-C. 안 본 것 — 「없다」가 아니라 「못 봤다」**

| # | 안 본 것 | 틀렸을 때의 영향 |
|---|---|---|
| 1 | **npb.jp 2024는 1구단만 봤다**(西武) | 다른 구단에 주석이 남아 있으면 「2024부터 없다」가 과장 |
| 2 | **npb.jp 18개 연도**(2002~05·07~12·14~18·20~21) | 주석 시작 연도와 마크업 변화를 모른다 |
| 3 | **ja.wikipedia 58개 연도** | 색·굵기 규칙이 몇 종인지 모른다. **1990이 이미 다르다** |
| 4 | **12구단 공식 드래프트 페이지 12개** | 위음성 전례가 있다(야쿠르트 Hawk-Eye). **「없다」의 근거로 쓰지 마라** |
| 5 | **스포츠 언론 robots·약관** | 후보에서 뺐지 판정한 게 아니다 |
| 6 | **`schedule.html` 이 어느 연도부터 있는가** | 2001 없음·2013 있음까지만 안다. 요구 ④의 소급 하한 미확정 |
| 7 | **2026 드래프트 당일에 주석이 부활하는가** | 2026-10-22 이후 재확인 필요. **지금 답할 수 없다** |

⚠**7번이 가장 중요하다.** 「2024부터 안 적는다」는 **표본 2시즌의 관찰**이고 **3번째가 다를 수 있다.**
