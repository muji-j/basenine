# 드래프트 — wikipedia 소스 구현 계획 (2026-09-06)

> **For agentic workers:** 이 계획은 **새 규칙을 만들지 않는다.** 규칙의 정본은
> `docs/sources/2026-09-04-draft-wikipedia-markup-rules.md`(369줄 · `S0~S9` · `INV-1~7` · `X-1~3`)이고,
> 설계 정본은 `docs/superpowers/specs/2026-09-04-draft-page-design.md` 다.
> **이 문서는 「무엇이 이미 있고, 무엇만 만들면 되는가」와 「무엇을 통과해야 채택인가」만 정한다.**

**목표:** 2023~2025 세 시즌의 **1위 지명 경합**을 화면에 낸다.
**왜 지금:** 그 세 시즌만 비어 있고, 그 이유는 **NPB 가 2023부터 페이지에 안 쓰기 때문**이다
(12구단 전수 0/12 · 경합 자체는 실제로 있었다).

## 0. ⚠먼저 읽어라 — 이 작업의 절반은 이미 끝나 있다

**조사·규칙·대조·배관이 전부 있다. 없는 것은 수집기·파서·적재 셋뿐이다.**

| 이미 있는 것 | 어디에 | 상태 |
|---|---|---|
| 마크업 규칙 · 파서 절차 `S0~S9` | `docs/sources/2026-09-04-draft-wikipedia-markup-rules.md` | **정본** |
| 불변식 `INV-1~7` · 교차검증 `X-1~3` | 같은 문서 §5 | **21개 연도 전수 성립** |
| npb 와의 대조 | 같은 문서 §2 | **불일치 0건**(40문장 · 72명단) |
| DB 스키마의 `origin` | `packages/store/migrations/019-draft.sql` | **있음**(`'npb' \| 'wikipedia'`) |
| 적재의 `(season, team, origin)` 삭제 범위 | `packages/store/tools/load-draft-archive.ts` | **있음** — npb 행을 안 지운다 |
| 화면의 출처·라이선스 표기 | `packages/web/src/draft-page.ts` | **있음**(`DraftOrigin` · `license` · CC BY-SA 문구) |
| L2 경계(격자를 재현하지 않는다) | 같은 파일 머리말 | **있음** |

⚠**그러므로 화면을 고칠 일이 거의 없다.** 데이터가 들어오면 이미 그려진다.

## 1. 만들 것 셋

### ⑴ 수집기 — `packages/archiver/src/draft-wiki.ts` + CLI

선례는 **`packages/archiver/src/draft.ts` · `cli-draft.ts`**(npb 쪽)다. 그대로 따른다.

| 규칙 | 값 | 왜 |
|---|---|---|
| URL | `https://ja.wikipedia.org/wiki/{YYYY}年度新人選手選択会議_(日本プロ野球)` | `S0` |
| 경로 | **`/wiki/` 만** — `/w/`·`/api/` 금지 | robots Disallow(문서 `S0`) |
| 간격 | `L1_MIN_DELAY_MS`(2,000ms) 이상 · 기본 3,000ms | L1 |
| UA | `buildUserAgent(contact)` — 기존 함수 그대로 | L1 · 예약 도메인은 이미 거부된다 |
| 조건부 요청 | **쓴다** — `Last-Modified` 가 온다(19/19) | ⚠**npb 와 다르다**(그쪽은 0/9). L7 이 여기서는 실제로 절약한다 |
| 아카이브 키 | `wikipedia/draft/{year}` | ⚠**`npb/` 아래에 두지 마라** — 출처가 다르다 |
| 사이드카 | `license = "CC BY-SA 4.0"` · 기사 URL · `Last-Modified` | `S9` · M4 · L3 |

⚠**연 1회 수집이다.** npb 쪽과 같은 층이라 일일 배치에 붙이지 않는다(런북 §0).

### ⑵ 파서 — `packages/parser/src/draft-wiki.ts`

**`S1~S8` 을 그대로 옮긴다.** 아래는 그중 **조용히 틀리는 것들**이라 다시 적는다:

- `S3` **rowspan/colspan 을 펼친다.** 안 펼치면 **2007 서부터 오른쪽 6팀이 한 칸씩 밀리고,
  밀린 값도 실재 선수명이라 눈으로 안 잡힌다.**
- `S4` 머리행은 **첫 칸이 `チーム` 또는 `指名順`** 인 행. ⚠**위치로 찍지 마라** — 배너가 머리행
  위인지 아래인지가 2010~2023 과 2024~ 를 가르는 **유일한 구조 차이**다.
- `S6` ⚠**`1巡目→` 와 `1巡目1` 은 다른 것이다**(육성 1라운드 vs 支配下 1순위).
  **화살표 유무가 유일한 구별**이고, 「`1巡目` 로 시작하면 1순위」로 짜면 **육성 선수가 드래프트 1위가 된다.**
- `S7` `---` 는 **미지명이지 미수집이 아니다**(M11). 이름은 `display` 와 `canonical` **두 벌**로
  저장한다 — 8건이 다르고 **어느 쪽도 항상 옳지 않다.** ⚠**이름으로 조인하지 마라**(M10).
- `S8` 경합 그룹은 **(행, 배경색)** 이다. ⚠**표 전체를 색으로 묶지 마라** — 색이 다른 행에서
  재사용된다(2013·2017·2023 실측). `#ccc` 는 추첨이 아니다.
- **굵기**: 셀에 `font-weight` 가 **없으면 굵고**, `normal` 이면 안 굵다(굵기의 출처는 표 자신).
  ⚠**문자열 매칭 금지** — 같은 표에 `normal;` 와 `normal` 이 공존한다(2019). **프로퍼티 단위로 파싱**한다.
- **예외 3건**(2007 `指名権剥奪` rowspan=5 · 2006 `不合意` · 2005·2015 `交渉権訂正` 산문)은
  문서 §3 의 표를 그대로 구현한다.

⚠**어디에도 안 맞으면 실패다**(M7). 빈 값으로 흘리지 마라.

### ⑶ 적재 — `load-draft-archive.ts` 확장

- 행마다 `origin='wikipedia'`.
- 삭제 범위는 **이미 `(season, team, origin)`** 이라 npb 행을 건드리지 않는다. **그대로 쓴다.**
- ⚠**같은 (시즌·구단·구획)에 두 출처가 들어오면 무엇이 이기는가를 적어라**(M1).
  이 계획의 답: **npb 가 이긴다**(공식 > 커뮤니티 · §2-4 신뢰 등급).
  wikipedia 는 **npb 가 말하지 않는 자리만** 채운다.

## 2. ⚠채택 게이트 — 이것을 통과하기 전에는 화면에 내지 않는다

문서가 정한 3단계를 그대로 쓴다.

| 게이트 | 무엇 | 통과 기준 |
|---|---|---|
| **G-A** | `INV-1~7` 을 우리 파서 산출에 건다 | **21개 연도 전수 성립** |
| **G-B** | `X-3` — 구단별 지명 명단을 npb 와 대조 | **불일치 0**(표기 차는 기록) |
| **G-C** | `X-1` — **2005~2022** 의 npb 경합 문장과 셀 단위 대조 | **불일치 0** |


⚠⚠**G-A 는 통과하지 못했다 — 그리고 통과한 것처럼 다시 쓰지 마라**(2026-09-06 검토 지적).

구현이 강제하는 것은 **`INV-1~6`** 이고 **`INV-7` 은 「0건」이 아니라 「안 쟀음」**이다
(웨이버 순서를 대조하려면 `schedule.html` 이 필요한데 아카이브에 안 받았다).
런북과 이 계획서가 한때 결과표에서 **게이트를 `INV-1~6` 으로 다시 정의해** 통과시켰다.
**그건 게이트를 푼 것이지 통과한 것이 아니다.**

**그래도 낸 근거**(사람이 판단할 자리이므로 근거를 적어 둔다):

| | |
|---|---|
| `INV-7` 이 지키려던 것 | **열 ↔ 구단 매핑**이 맞는가 |
| 실제로 그 자리를 지키는 것 | **이름 겹침 전단사**(`resolveDraftWikiColumns`) — **못 맞추면 던진다.** 연도별로 INV-7 보다 강하다 |
| 독립 확인 | **npb 1순위 ↔ 위키 획득행이 2023·2024·2025 에서 12/12/12 = 36/36 일치**(검토자 실 DB 재현) |
| `INV-7` 의 **고유** 가치 | **웨이버 순서** 축 — ⚠**이 화면은 그 축을 안 쓴다**(`waiver_dir` 는 전건 NULL 이고 화면이 「지명순은 출전에 없다」고 적는다) |
| 그래도 남는 미검증 | **「누가 누구와 겹쳤나(그룹 구성)」와 낙첨 행** — 그 축의 정답지가 저장소에 없다 |

⚠**이 표를 「그러므로 괜찮다」로 읽지 마라.** 여기 적은 것은 **무엇이 안 지켜졌고 무엇이 그 자리를
대신하는가**이지 게이트가 충족됐다는 말이 아니다. `schedule.html` 을 받게 되면 **INV-7 을 걸어라.**


⚠**G-C 가 이 작업의 유일한 진짜 검증이다.** `INV-1~6` 은 **내부 정합성**이라
**색을 통째로 잘못 읽어도 같이 통과한다**(문서 §5 가 그렇게 경고한다).
**색의 의미를 지탱하는 것은 `X-1` 하나뿐이다.**

⚠**2023~2025 는 대조 상대가 없다.** 그래서 이 세 시즌은 **G-C 를 통과한 파서**가 낸 값이라는
것 말고는 근거가 없다 — **화면이 그 사실을 말해야 한다**(이미 CC BY-SA 문구가 그 자리에 있다).

## 3. 시험

- 픽스처는 **실물 HTML 을 `.html.gz` 로 고정**한다(`packages/parser/test/fixtures/`).
  ⚠**합성 픽스처로 검증하지 마라** — npb 파서에서 실제로 데였다: 합성 픽스처에 결과 칸이 0개여서
  **구형 경로가 항상 빈 배열이어도 시험이 전부 초록**이었다(런북 §6 G1).
- 개발 루프에서 **ja.wikipedia 에 반복 접속하지 않는다**(작업규칙 11).
- 새 시험은 **고치기 전 코드에서 떨어지는지** 확인하고 채택한다(뮤테이션 · 작업규칙 9).
- 분모를 표기한다. **FAIL 과 ERROR 를 따로 센다.**

## 4. 배포 경로 — ⚠여기를 빼먹으면 로컬만 최신이 된다

드래프트 원본은 **릴리스 자산 `draft-archive.tar`** 로 CI 에 건너간다(런북 §0).
지금 그 tar 는 **`archive/npb/draft` 만** 담는다.

→ **`archive/wikipedia/draft` 를 같이 담도록 넓혀야 한다.** 안 넓히면
**CI 는 위키 원본을 못 받고, 화면은 그대로 비어 있다** — 그리고 **에러가 아니라 빈 화면**이라
아무도 결함으로 못 읽는다(이 저장소가 이미 겪은 모양).

⚠**적재 스텝은 안 고쳐도 된다** — `load-draft-archive.ts data/archive …` 가 아카이브 뿌리를 받으므로,
로더가 위키를 읽게 되면 그 스텝이 그대로 집는다.
