# 디자인 3단계 — 서체를 화면에 붙인다 (2026-09-08)

정본: `../specs/2026-09-07-design-direction.md` **§5-A ~ §5-F**.
파이프라인은 **이미 있다**(커밋 `72b7423` · `scripts/fonts.ts` · `npm run build:fonts`).
**이 단계는 그 산출물을 화면에 배선하는 것**이다.

⚠**파이프라인이 만드는 계약**: `dist/assets/fonts/manifest.json` —
`cssFamily` · `reservedFontName` · `charsetSha256` · **웨이트별 해시 파일명** · `tabularByDefault`.
**CSS 배선은 이 매니페스트를 읽는다.** 파일명을 손으로 적지 마라(해시가 매번 바뀐다).

---

## 0. ⚠파이프라인이 남긴 사실 — 이 계획의 전제

| | 실측 |
|---|---|
| 쓰이는 글자 | **1,646자**(漢字 1,350) — ⚠**내 추정 상한 1,600 을 넘겼다** |
| **JP 한 웨이트** | **297 KiB**(plex) / 257 KiB(noto) — ⚠**내 추정 「80~200KB」가 한 자리 틀렸다** |
| **3웨이트 스택 합** | **Plex 960.2 KiB · Noto 814.3 KiB** |
| 라틴 한 웨이트 | 12~15 KiB |
| 파일 수 | **+16장**(9,549 → 9,565 / 20,000 = 47.8%) |
| 숫자 폭 | ⚠**넷 다 10자가 같은 폭** — `tnum` 기능이 없어도 **자릿수는 안 흔들린다** |
| 서체가 레이아웃을 깨는가 | ⚠**안 깬다** — 행 2,981개에서 **두 줄 된 행 0**(§5-D) |

---

## 1. 로딩 전략 — ⚠**내가 정한다**(근거를 적는다)

**960 KiB 를 한 번에 받게 하지 않는다.**

- **`400` 만 `preload`** 한다(JP 297 + 라틴 14 = **약 311 KiB**). 본문 대부분이 400 이다.
- **`600`·`700` 은 `preload` 하지 않고 `font-display:swap`** 으로 뒤따라오게 한다.
- ⚠**`swap` 이 안전한 근거가 있다** — §5-D 실측에서 **행이 두 줄 되는 곳이 0** 이었다.
  **폰트가 바뀌어도 레이아웃이 안 밀린다.** `optional` 은 느린 회선에서 **서체를 아예 건너뛰어**
  「고른 이유」가 사라지므로 쓰지 않는다.
- ⚠**「기본(システム)」을 고른 사람은 요청이 0건**이어야 한다(§7-3). **시험으로 고정한다.**
- ⚠**고르지 않은 서체는 받지 않는다** — 세 벌을 다 `preload` 하면 안 된다.

⚠**이건 측정 없이 고른 값이 아니다** — 297 KiB 와 「행이 안 늘어난다」 둘 다 실측이다.
**다만 실회선에서 재 보지는 않았다.**

## 2. 패밀리 이름 — **`BN Sans` / `BN Sans JP`**

⚠**IBM Plex 의 예약 서체명이 `"Plex"`** 이고 OFL §1 이 **글리프 삭제도 개변**으로 보므로
**부분집합은 개변판**이다(§5-F). → **CSS 패밀리명에서 `Plex` 를 뺀다.**
⚠**안전한 쪽으로 고른 기본값이지 법률 판단이 아니다.** 사용자가 원하면 되돌린다.
**Noto 는 예약명이 `Source` 라 안 걸린다** — 그대로 쓴다.

⚠**매니페스트의 `reservedFontName` 이 이 판단의 근거를 담고 있다. 읽어라.**

## 3. 전환 UI — 테마 설정 옆

**3종**: `기본(システム)` / **`IBM Plex`(초기값)** / `Noto Sans JP`.
⚠**초기값은 IBM Plex 다**(사용자 결정 · §5-B).

**실패 경로 4종을 반드시 구현한다**(§7-3):

| 상황 | 해야 할 것 |
|---|---|
| 폰트 로드 실패 | 시스템으로 떨어지되 **선택은 그대로 저장**. ⚠**선택을 조용히 고쳐 쓰지 마라** |
| 빠른 재선택(경쟁) | **마지막 조작이 이긴다.** 늦게 온 이전 선택의 로드는 **버린다** |
| localStorage 실패 | `try/catch` · **저장값 없는 상태로 정상 렌더** |
| 「기본」 선택 | ⚠**웹폰트 요청 0건** — 시험으로 고정 |

⚠**전환 시 표의 자릿수가 흔들리는지 실측하라**(§5-B). 숫자가 주역인 사이트다.

## 4. ⚠CI 배선 — **지금 CI 에서 안 돈다**

`daily.yml` 이 `npm run build:web` 이 아니라 **`build.ts` 를 직접** 부른다(§5-F).
→ **워크플로에 폰트 단계를 더한다.**

⚠**비용을 CI 에서 재라** — 지금 수치는 **이 기계에서만** 잰 것이고
**훑기가 캐시 상태에 따라 7배(22.7~154.4초) 흔들린다.**
⚠**CI 무료 분이 스케줄만으로 88% 차 있다**(§6). 예산 안에 안 들어오면
**서체를 줄이거나 주기를 바꾼다** — 그때 정한다.

## 5. ⚠누락 게이트가 이미 물고 있다

`▸`(U+25B8)·`◂`(U+25C2) 가 네 서체 모두에 없어 **폰트 빌드가 종료코드 1** 이다.
**`▶`·`◀` 로 바꾸는 작업이 진행 중이다**(별건).
⚠**이 단계에 들어오기 전에 그게 통과해야 한다.**

⚠**게이트를 끄고 진행하지 마라.** 이 게이트가 없으면 부분집합은
**「대개 맞는 화면」**이 되고 그건 이 프로젝트가 가장 나쁘게 치는 상태다.

## 6. 게이트

- ⚠**세 선택지 각각에서** 홈·선수·순위 × 390/1280 을 **실제로 굽고 재라** —
  **행이 두 줄 되는 곳 0 · 가로 넘침 변화 0 · 잘림 변화 0**(§5-D 의 그 방법).
  ⚠**적용을 먼저 증명하라**(로드된 face 수 + 같은 글자 폭 변화). **증명 안 되면 「측정 실패」로 찍어라** —
  §5-D 에서 프로브가 **세 번** 거짓 통과를 냈다.
- **대비 시험 통과**(서체가 바뀌어도 잉크는 그대로여야 한다).
- **`prefers-reduced-motion`** 과 무관해야 한다.
- 빌드 파일 수 · 링크 검사 · 종료코드 사유.

## 7. ⚠안 정한 것

1. **웨이트 500 을 만들지 안 만들지** — 지금은 500→400 으로 붙는다(합성 굵게 아님).
   표 머리가 400 으로 보이는 것이 문제면 **+4장 · 약 640 KiB**.
2. **실회선에서의 체감** — 297 KiB 가 실제로 얼마나 걸리는지 안 쟀다.
3. **Mac·Safari·Firefox** — 부분집합을 실제 브라우저에 씌워 본 적이 없다(§5-D 는 Google 슬라이스였다).
