## 2. 설계 — 설계서를 그대로 옮긴 것만

### 2-1. `streak-view.ts` — **왜 새 파일인가**

지금 「以上」·「最大」의 서식은 `player-page.ts` 의 **지역 함수**(`den`·`inTextOf`·`maxOf`·`appText`)다.
순위표가 같은 값을 그리려면 **두 벌**이 되고, 그 순간 §3-3-A 가 정한 규칙
(두 사유가 겹칠 때 `保有範囲内では最大…`)이 한쪽에만 남는다.

→ **한 벌로 뽑는다.** 새 파일인 이유는 `player-page.ts` 와 `pages.ts` 가 **서로를 안 import 하는 편이
낫기 때문**이다(`pages.ts` 는 이미 `player-page.ts` 의 타입만 가져온다).

```ts
export function streakDen(...parts: string[]): RawHtml          // 「·」로 잇는다. 빈 것은 뺀다
export function appearanceText(n: number, atFloor: boolean): string        // 「50登板」/「50登板以上」
export function inningsStreakText(lowerOuts, exact, atFloor): string       // 「49回」/「23.1回以上」
export function inningsStreakMax(upperOuts, exact, atFloor): string        // ""/「最大25.1回」/「保有範囲内では最大…」
```

⚠**`atFloor` 는 호출자가 정한다** — 시즌 모드에서는 `atRangeStart` 가 「以上」이 **아니다**
(`PitchingStreak.atRangeStart` 주석). 이 파일은 그 판단을 안 한다.

### 2-2. `query.ts` — 행 만들기

```ts
export interface StreakRankRow {
  playerId: string; name: string; teamCode: string;
  rank: number | null;         // rankStreaks 가 준다
  value: string;               // 이미 다듬은 글자 — 「50」/「23.1回以上」
  den: string;                 // 분모 ⑴ (+ 이닝 축이면 최대) — 「57登板」/「最大25.1回 · 47登板」
  from: string; to: string;    // 분모 ⑵
}
export interface StreakRankPanel {
  id: string; termKey: string;               // 라벨은 용어집에서(M1)
  rows: StreakRankRow[];
  candidates: number;                        // 그 축에 기록이 있는 선수 수 — **자른 것을 말한다**
  scannedUnit: "試合" | "登板";
  hasUnranked: boolean;                      // 「以上」 행이 있는가 — 각주가 이것을 본다
  isInnings: boolean;                        // 이닝 축의 각주(33.1 = 33과 1/3)를 켠다
}
```

⚠**`value`·`den` 을 서버가 다듬어 보낸다** — `RankRestRow` 가 이미 그 규약이고(M1),
렌더러가 다시 포맷하면 자릿수·이닝 표기가 어느 날 갈린다.

⚠**분모를 타입이 강제한다**(M2): `den` 은 `string`(옵셔널 아님)이고 `from`/`to` 도 필수다.
**분모 없는 행을 만들 수 없다.**

**컷**(설계 §4-1):

```ts
const ranked = rankStreaks(entries);
const top = ranked.filter((r) => r.rank !== null && r.rank <= STREAK_RANK_ROWS);
const floor = top.length > 0
  ? Math.min(...top.map((r) => r.value))
  : (ranked.map((r) => r.value).sort((a, b) => b - a)[STREAK_RANK_ROWS - 1] ?? -Infinity);
const rows = ranked.filter((r) => (r.rank !== null && r.rank <= STREAK_RANK_ROWS) || (r.rank === null && r.upper >= floor));
```

⚠**순서는 `rankStreaks` 가 준 순서 그대로**다 — 다시 정렬하지 않는다(M1 · 정적 생성이라 흔들리면 diff 다).

**구단**: 투수 `pitchingTeamOn(db, id, season, competition, streak.to)` ·
타자 **`battingTeamOn`**(신설 · `batting_line.side`). ⚠**`teamCodeOf` 를 안 쓴다**(설계 §7).
⚠**못 찾으면 행을 뺀다**(M11) — 11-1 과 같은 규칙.

### 2-3. `pages.ts` — 표

`RankingCategory` 에 **선택 필드** `streaks?: StreakRankPanel[]` 를 더하고, 있으면
`categoryPanels` 대신 `streakCategory` 를 그린다.

⚠**`RankingPanel` 을 재사용하지 않는다**(설계 §2) — `rank === null` 의 뜻이 정반대다.

### 2-4. 상수

```ts
/** 연속 기록 순위표에 싣는 확정 순위의 상한. ⚠**화면에도 적는다**(M3의 정신) */
export const STREAK_RANK_ROWS = 10;
```

⚠**`RANKING_PAGE_ROWS`(50) 를 안 쓴다** — 근거가 다르다(설계 §4-3/§4-4).

## 7. 실행 결과 (2026-09-07 · 계획과 어긋난 곳 포함)

### 7-1. 뮤테이션 검사 — **11건 심어 11건 다 잡혔다. 단 첫 판에서 2건이 안 잡혔다**

⚠**그 2건이 이 검사의 소득이다** — 시험이 약한 것을 **시험을 읽어서는 못 봤고, 심어 봐야 보였다.**

| **렌더러가 행을 다시 정렬한다** | **FAIL 0** ⚠ | FAIL 1 |
| 행에서 분모(`den`)를 뺀다 | FAIL 2 | — |
| 각주에서 「N人のうち M人」을 뺀다 | FAIL 1 | — |
| **표 머리 라벨을 문자열로 박는다** | **FAIL 0** ⚠ | FAIL 1 |

| 이닝 각주를 **항상** 붙인다 | FAIL 1 | — |

⚠**안 잡힌 2건의 사유가 서로 다르다:**

1. **재정렬** — 시험 픽스처의 `playerId` 가 `aaa·bbb·ccc` 순이라 **사전 순 정렬과 결과가 같았다.**
   「순서를 본다」고 적었지만 **아무것도 구별하지 못하는 순서**를 보고 있었다.
   → 주어지는 순서를 `ccc·aaa·bbb` 로 바꿨다.
2. **라벨 박기** — 표 머리를 `連続無失点登板` 로 박아도 **탭 라벨은 여전히 `termLabel(p.id)`** 라
   화면 어딘가에 옳은 이름이 남았고, 시험이 그것을 보고 통과했다.
   → **표 자신이 무엇의 표인지 말하는 두 자리**(`aria-label` 과 머리 버튼)를 본다.

### 7-2. 계획과 어긋난 것 넷

1. **`subGroup` 을 안 썼다.** 지표 탭은 부문이 셋이라 `subGroup(prefix, c.id)` 가 필요한데,
   연속 기록 부문은 **하나뿐**이라 한 단계를 더 두면 그룹 이름이 **`rankstreak-streak`**
   — 이름이 자기를 두 번 말한다. 그룹을 그대로 쓴다.
2. **`streakSpanText`(home-page.ts)를 공용 함수로 뺐다.** 지시에 없었지만 **같은 기간 표기**를
   두 화면이 그리게 되므로 M1 이 걸린다. `streak-view.ts` 의 `streakSpan` 이 정본이고
   홈은 그것을 부른다.
3. **이름·구단을 「후보를 만들 때」 정하게 고쳤다.** 처음에는 컷 뒤에 정했는데, 그러면
   못 찾은 행이 **표에서만 빠지고 각주의 분모(`candidates`)에는 남아** 「162人のうち13人」이
   조용히 틀린 수가 된다(M2). ⚠**빌드 산출물에서 이 상태를 실제로 본 것은 아니다** —
   실측 결측 0건이라 **아직 안 났을 뿐**이고, 그래서 고쳤다.
4. ⚠**§2-2 의 타입 초안과 실물이 다르다** — 초안을 안 고치고 여기 적는다.
   `den` 한 칸이 아니라 **`scanned`(분모 ⑴)와 `max`(이닝 축의 상한)를 나눠 든다**(둘은 다른 사실이다) ·
   `termKey` 를 따로 두지 않고 **`id` 가 곧 용어집 키**다(두 이름을 두면 어긋난다) ·
   `hasUnranked` 는 필드가 아니라 **렌더러가 행에서 센다**(들고 다니면 행과 어긋날 수 있다).
