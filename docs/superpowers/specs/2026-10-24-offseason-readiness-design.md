### D3. 予告先発 연도 — 결정적 규칙 · 지난 날짜는 맥박만 — `load-starters.ts:76-83`(`resolveGameDate`) 교체

1. 후보 해 `C = { Y′ ∈ {Y−1, Y, Y+1} | Y′-MM-DD 가 실재한다 }`(Y = 취득일의 해 · 실재 = `Date.UTC` 왕복이 같은 Y·M·D — **자동 정규화 금지**: `2027-02-29` 를 `03-01` 로 넘기지 않는다).
2. `C = ∅` → **파싱 실패**(M7 · `failed` +1 · 종료 1 · 그 파일은 `starters_fetch`·`probable_pitcher`·`player` 어느 표도 안 바꾼다).
3. `lag(Y′) = 일수(Y′-MM-DD) − 일수(취득일)`. 고르는 것은 `|lag|` 가 가장 작은 `Y′` · 동률이면 `lag < 0`(과거) 쪽.
4. 고른 `|lag| ≤ 183` 이면 받고 **`|lag| ≥ 184` 면 2 와 같은 실패.** ⚠세 해가 다 실재하면 이웃 후보 간격이 365·366일이라 `|lag| ≤ 183` 이 늘 성립한다 — 3·4 의 실패는 2/29 에서만 난다.
5. 받으면: `lag ≥ 0` → 지금처럼(예고 행 · 휴식 공표) · **`lag < 0` → `starters_fetch` 한 행만**(게시 날짜 · `no_games` 는 페이지대로) — `probable_pitcher`·`ensurePlayer` 는 안 쓰고 요약에 「지난 날짜 게시 N건(맥박만)」. 옛 갈래(`1월 취득 ∧ 12월 게시 → null`)도 여기로 흡수된다.

- 근거: 실측 68회 전부 0·+1일(R4) — 음수는 비시즌의 낡은 페이지뿐이다. ⚠낡은 페이지가 옛 예고의 `fetched_at` 을 올리면 「예고보다 늦은 휴식 공표」 순서(9/11 D1-B · PR-3 철회 판정)가 뒤집힌다 — 맥박만이 그것도 막는다. 비용: 자정 직후 어제 게시를 다시 보면 그 예고 행을 안 갱신한다(관측 0/68).

### D4. 빌드 시즌은 DB 에서 유도한다 — `build.ts` 세 번째 인자 `auto` (조정자 결정 A)

## 5. 기각한 안

- **11월을 「시즌 종료 증거가 있을 때만」 받기(선택지 (b)) · 아카이버 판정에 `seasonIsOver` 쓰기** — 아카이버는 DB 를 안 열어 `update.ts` 가 값을 넘겨야 하고(인자 · 배선 · 시험이 는다), 그 값은 JS 적재(G1)에 묶여 차단이 길면 11·12월 404 가 계속 1 이다. (a) 는 DB 없이 결정적이고, 빠질 수 있는 진짜 11월 경기는 D1-B 가 이틀 뒤 막는다.
- **9/11 D7 의 404 관측 사이드카 + `--expect-month` + 36시간 창** — 관측이 없으면 「확인 불가 → 1」이라 **차단 중의 1월이 blocking** 이 되어 PR-2a ② 와 부딪힌다. 막으려던 「요청 안 함 · 경로 오류」는 D2 의 `MAX + 1` 과 3월의 D1 이 잡는다.
- **9/11 D8 `zeroComparisonVerdict`** — `crosscheck.ts` 관문의 종료 코드를 한 갈래 바꾼다 = 사용자 결정(2026-10-02 「관문 판정 불변」)을 건드린다. D6 은 관문을 안 바꾸고 같은 목적을 이룬다.
- **명시 목록의 순서를 지키고 첫 원소가 최신이 아니면 1** — 이것도 결정적이지만 「순서가 뜻을 갖는 목록」이 남는다. `auto` 가 기본이 된 뒤 명시 목록은 시험·로컬용이라 정렬이 단순하다.
- **予告先発 404 를 맥박 행으로 적재** — `starters_fetch.no_games` 가 `NOT NULL CHECK (0,1)` 이라 「페이지 없음」을 담을 자리가 없다(M11 · 셋째 상태는 표 재작성).
- **`CHECK (competition IN …)` 마이그레이션** — SQLite 는 제약 추가에 표 재작성이 필요하다 · 주석 하나에 과하다.
