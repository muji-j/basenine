# 따라잡기 창이 「덜 받은 날」을 다시 받게 한다 — 설계 (감사 C10)

- 날짜: 2026-09-26
- 대상: `scripts/update.ts` 의 `collectedThrough()` · `scripts/date-window.ts` 의 `targetDates()`
- 근거: `docs/audits/2026-09-25-multi-dimensional.md` §10-2 C10(다른 벤더 블라인드 반증 · 재현 확정 · P2)
- 콜드 리뷰: `shiro-core:gpt-reviewer`(`-m gpt-5.6-sol` · `high` · `ok=true`) — **조건부**, 5건 반영:
  ① DB 읽기 실패를 표현할 갈래가 없었다 → `loaded` 도 `null` 가능(D1) · ② 경기 폴더 판별이 적재기보다 느슨했다 → 한 벌(D2) ·
  ③ **`since - 1일` 을 넘기는 안은 간격이 정확히 상한(7)일 때 따라잡기를 통째로 끈다(재현)** → 명시적 옵션(D4) ·
  ④ 읽기 순서 미정 → DB 먼저·아카이브 나중(D3) · ⑤ 「대개 304」는 틀렸다(npb.jp 는 검증자를 안 준다) → 비용 서술 정정.

## 1. 문제

수집 창의 기준점은 `SELECT MAX(game_date) FROM game WHERE status = 'played'`(= `since`)다.
`targetDates()` 는 **어제**를 늘 넣고, `since` 와 어제 사이가 2일 이상이면 그 사이(`since+1` ~ 어제 전날)를 더한다(`MAX_CATCHUP_DAYS = 7` 이하일 때만).

적재기는 **끝나지 않은 경기**(`box.status === "inProgress"`)를 저장하지 않고 건너뛴다(`packages/store/tools/load-archive.ts` 의 `inProgress` 카운터 · 로그 한 줄뿐).
그러므로 D 날 23:30 JST 실행이 D 의 경기 일부만 저장하면(끝난 것만) `since = D` 가 되고, **D 의 진행 중이던 경기는 DB 에 없다.**

정상 흐름에서는 다음 날(D+1) 아침 실행이 「어제 = D」를 받아 메운다. 그런데 **D+1 의 실행이 전부 실패**하고 다음 성공이 D+2 이후면:
- D+2 아침: 어제 = D+1, `since = D` → 간격 1 → 창 = [D+1] — **D 는 빠진다.**
- D+3 아침: 어제 = D+2, 간격 2 → 창 = [D+1, D+2] — **D 는 여전히 빠진다**(창이 `since` 다음 날부터).

→ D 의 그 경기는 **자동으로는 영원히 안 받힌다**(수동 `refetch_dates` 로만). 반증자 재현:
`targetDates(new Date('2026-09-12T22:00:00Z'), {collectedThrough:'2026-09-10'})` → `["2026-09-11","2026-09-12"]`(09-10 없음).

「하루 전체 실행 실패」는 실재한 적이 있다(2026-08-31 · Actions 분 소진으로 배포가 스텝 0개로 죽음 · CLAUDE.md §6).

## 2. 지켜야 할 기존 약속

1. **정상·휴식일에는 요청이 1건도 안 는다**(CLAUDE.md §6 · 시험이 고정). ← 가장 무거운 제약(L1).
2. 상한(`MAX_CATCHUP_DAYS`)을 넘으면 따라잡지 않는다(백필은 사람의 일).
3. **모르면 안 넘긴다**(M11) — 모르는 것을 「어제」로 메워 빈 날을 건너뛰지 않는다.
4. `date-window.ts` 는 store 배럴을 가져오지 않는다(잎 서브패스·상대경로만 · `scripts/test/refetch-wiring.test.ts` I1).
5. 시계는 진입점에서 한 번(M6).

## 3. 안

### 안 A — 간격이 있으면 `since` 도 넣는다 (반증자의 단기안) — **기각**
간격 1 이상이면 `since` 를 창에 넣는다. D+2 아침(간격 1)에 D 를 받으려면 **간격 1 에서도** 넣어야 하는데,
간격 1 은 **휴식일 다음 날마다** 생긴다(월요일 휴식 → 화요일 아침) — 그날마다 이미 다 받은 날의 경기 전부에 조건부 요청이 나간다
(경기 6 × 4장 ≈ 24요청). 약속 1 을 깬다.

### 안 B — `since` 날이 **덜 받혔는지**를 아카이브와 DB 로 대조한다 — **채택**
`since`(= 마지막으로 경기가 저장된 날) **하나만** 본다:
- 아카이브의 그 날 경기 폴더 목록(`data/archive/npb/scores/<YYYY>/<MMDD>/<slug>/` — 폴더 경로가 곧 `game_id` 모양 `YYYY/MMDD/<slug>`)
- DB 의 그 날 `game` 행(상태 무관 — `played`·`notPlayed` 둘 다)

폴더는 있는데 행이 없는 경기가 **하나라도** 있으면 `since` 는 「덜 받은 날」이다 → **`since` 자신을 창에 넣는다**(4장 D4 — 명시적 옵션).
⚠~~창 계산에 `since - 1일` 을 넘긴다~~ 는 **틀린 안이었다**(콜드 리뷰 ③ · 재현): 간격이 정확히 상한(7)일 때 `since - 1일` 로는 간격이 8 이 되어
**따라잡기가 통째로 꺼진다**(창이 [어제] 하나로 무너진다) — 예시로 든 간격 1~3 에서는 안 드러나는 결함이었다.

왜 `since` 하나만 보는가:
- 위 실패 시나리오에서 덜 받은 날은 **정확히 `since`** 다 — D+1 에 실행이 하나라도 성공했으면 그 실행이 「어제 = D」로 메웠고, 성공한 게 없으면 `MAX(played)` 가 D 에 머문다.
- 더 오래된 날을 보면 「영원히 덜 받힌 날」(예: 서스펜디드로 행이 안 생기는 경기)이 `since` 를 과거로 끌어 **따라잡기 상한을 넘겨 따라잡기 자체가 꺼진다**(약속 2 가 역으로 작동). `since` 하나로 한정하면 다음 경기일에 `MAX(played)` 가 넘어가는 순간 저절로 풀린다.

비용: 덜 받은 날이 있을 때만 그 날 경기의 페이지를 **다시 받는다**. 정상·휴식일에는 대조가 「완결」로 나와 창이 그대로다 — **요청 0 증가**(약속 1).
⚠아카이버는 창에 든 날의 경기마다 요청을 보낸다(`packages/archiver/src/archive.ts` 의 `prepareUrl` — 폴더가 있다고 건너뛰지 않는다) — 그래서 D 를 창에 다시 넣으면 진행 중이던 경기가 **실제로 다시 받힌다.**
⚠~~대개 304~~ 가 아니다(콜드 리뷰 ⑤) — 조건부 헤더를 보낼 자리는 있지만 **npb.jp 가 검증자(ETag·Last-Modified)를 하나도 안 준다**(같은 파일 주석의 실측 · 사이드카 3,000 표본에 둘 다 0건). 그래서 **매번 200 전체 본문 + sha 비교**다 — 덜 받은 날 한 번에 경기 수 × 4장(더블헤더 포함 대개 24~28장)을 온전히 받는다.

실측(2026-09-26 · 로컬 `data/archive` 와 `data/bb.sqlite` · 읽기 전용):
- 폴더 경로와 `game_id` 가 같은 모양이다 — 마지막 경기일 2026-08-16 에서 행 6 · 폴더 6 · 어긋남 0(`2026/0816/b-f-21` 등).
- **보유 아카이브 전 날짜 1,555일 · 경기 폴더 7,805개 중 「폴더는 있는데 행이 없는」 것 0건** — 이 신호는 평소에 헛경보를 내지 않는다.
  ⚠로컬 아카이브는 08-16 까지다(CI 수집분은 안 쟀다).

### 안 C — 적재기가 건너뛴 진행 중 경기를 표에 남긴다 — 보류
`pending_game` 같은 표를 만들어 적재기가 `inProgress` 를 기록하고 나중에 저장되면 지운다. 가장 정확하지만 **마이그레이션(데이터 계약 변경)**이고
안 B 가 같은 시나리오를 스키마 변경 없이 덮는다. 안 B 가 틀린 것으로 드러나면 그때 간다.

## 4. 결정 (안 B)

D1. 판정은 **순수 함수**로 `scripts/date-window.ts` 에 둔다:
`sinceStatus(archived: readonly string[] | null, loaded: readonly string[] | null): { status: "complete" | "incomplete" | "unknown"; missing: number }`
- `archived` = `since` 날의 아카이브 경기 id 목록 · `loaded` = `since` 날의 DB 경기 id 목록(상태 무관). **둘 다 `null` 일 수 있다**(못 읽음 — 콜드 리뷰 ①).
- 어느 쪽이든 `null` → `unknown`(`missing: 0`) — **넓히지 않는다**(약속 1 쪽으로 기운다 · 이유를 로그로 말한다). ⚠`loaded` 실패를 빈 목록으로 두면 그날 경기 전부를 「덜 받음」으로 오판한다.
- `archived` 에 `loaded` 에 없는 id 가 있으면 `incomplete`(`missing` = 그 수).
- 그 밖(`loaded` 에만 있는 id 포함 — 아카이브가 지워진 경우)은 `complete`.
D2. **경기 폴더 판별은 적재기와 한 벌이다**(M1 · 콜드 리뷰 ②). 적재기의 `gameFromPath` 판정 — `<season>/<MMDD>/<slug>/box.html.gz` 가 있고
   slug 가 `-` 로 **3조각 이상**이며 **마지막 조각이 수**인 것 — 을 **가져오는 것이 없는 잎 모듈**(`packages/store/src/game-slug.ts` · 서브패스 `@bb-app/store/game-slug`)로 옮겨
   `load-archive.ts` 와 `update.ts` 가 같이 쓴다(PR #18 의 `refetch-limit` 선례). 임의 이름 폴더(`.staging` 등)는 경기가 아니다.
D3. I/O 는 `scripts/update.ts` 의 `collectedThrough()` 가 한다. **읽는 순서를 고정한다**(콜드 리뷰 ④):
   ① **DB 를 먼저** — 읽기 전용 연결 하나에서 `MAX(game_date) WHERE status='played'` 와 그 날의 `game_id` 목록을 **한 트랜잭션**으로 읽는다.
   ② **그다음 아카이브** — 그 날 폴더를 D2 판정으로 거른다.
   스냅샷 뒤에 새 폴더가 생기면(다른 수집이 겹친 경우) 「덜 받음」으로 읽혀 **더 받는 쪽**으로 틀린다 — 빠뜨리는 쪽이 아니다.
   ⚠같은 아카이브에 수집기 둘을 동시에 돌리는 것은 원래 지원하지 않는다(일일 잡은 `concurrency: daily-collection` 으로 직렬).
D4. `targetDates()` 에 **명시적 옵션** `includeSince?: boolean` 을 더한다(콜드 리뷰 ③):
   - 간격은 **실제 `since`** 로 잰다(지금 그대로) — `since` 를 앞당기지 않는다.
   - `includeSince` 이고 `since` 가 어제보다 이르며 간격이 상한(`MAX_CATCHUP_DAYS`) **이하**면 창 맨 앞에 `since` 를 더한다.
   - 간격이 상한을 넘으면 지금처럼 따라잡지 않는다(백필은 사람의 일 — `since` 도 안 넣는다).
   - `since` 가 어제거나 그 뒤면 아무것도 더하지 않는다(어제는 이미 창에 있다 · 중복 없음).
   ⚠표 시험(간격 0·1·2·6·7·8)으로 고정: 간격 1 → [D, 어제] · 2 → [D, D+1, 어제] · 7 → [D … 어제](8일) · 8 → [어제] · 0 → [어제](=D).
D5. `update.ts` 는 판정 결과를 **한 줄로 말한다** — `incomplete` 면 「마지막 경기일 D 에 저장 안 된 경기 N건 — D 도 다시 받는다」, `unknown` 이면 무엇을 못 읽었는지.
D6. 재수집 입력(`BB_REFETCH_DATES`)·`--date` 가 있으면 이 판정을 하지 않는다(지금도 그 경우 `collectedThrough` 를 안 부른다).

## 5. 시험

- 순수 함수 `sinceStatus`: 완결 · 덜 받음(폴더 3 / 행 2 → `missing` 1) · 아카이브 못 읽음 · **DB 못 읽음** · `loaded` 에만 있는 id(완결).
- 잎 모듈 `game-slug`: 정상 slug · 조각 2개 · 마지막이 수가 아님 · `box.html.gz` 없음 → 경기 아님. `load-archive.ts` 가 **같은 함수**를 쓰는지(소스 정적 검사).
- 창 `targetDates(..., { collectedThrough: D, includeSince: true })`: 간격 0·1·2·6·7·8 표. **`includeSince` 가 없거나 거짓이면 지금과 한 글자도 다르지 않다**(요청 0 증가를 고정 — 기존 시험 유지).
- `update.ts` 배선: 소스 정적 검사(`refetch-wiring.test.ts` 와 같은 방식)로 `collectedThrough` 가 DB→아카이브 순으로 읽고 `sinceStatus` 결과가 `incomplete` 일 때만 `includeSince: true` 를 넘기는지.
- 고치기 전 코드에서: 「덜 받은 날이 창에 들어간다」·「간격 7 에서도 들어간다」가 떨어져야 한다.

## 6. 뒤집힐 조건

- 적재기가 진행 중 경기 말고도 **폴더만 있고 행이 없는** 경우를 정상적으로 만들게 되면(예: 새 상태를 행 없이 건너뜀), 안 B 는 그날을 매번 「덜 받음」으로 본다 — 그 상태를 행으로 남기거나 판정에서 뺀다.
- 서스펜디드처럼 **다음 경기일까지** 행이 안 생기는 경기가 잦아지면 그 사이 매 실행 그 날짜에 조건부 요청이 나간다 — 잦아지면 안 C 로 간다.
