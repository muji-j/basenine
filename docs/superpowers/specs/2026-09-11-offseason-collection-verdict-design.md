# 휴식기·오프시즌의 수집 판정 — 「며칠 지났나」가 아니라 「받았어야 할 경기를 못 받았나」로

> **상태**: 설계(콜드 리뷰 전) · 2026-09-11
> **결정**: 사용자가 네 선택지 중 **「일정과 대조해 판정」**을 골랐다(2026-09-11).
> 기각한 셋은 §9.
> **마감**: 첫 휴식 구간은 **2026 정규시즌 종료 → 클라이맥스 시리즈(CS) 사이, 10월 초**다(§1-1).
> 문서에 적혀 있던 「11월 초 전에 정한다」(`docs/operations.md`)는 **틀렸다.**

---

## 0. 한 줄 요약

수집 잡이 「최신 경기가 2일보다 오래됐다」로 실패하는 규칙을, **「NPB 가 열린다고 공표한 경기를
우리가 못 받았다」**로 바꾼다. 경기가 없는 기간(휴식·오프시즌)에는 공표된 경기가 없으므로
**날짜를 코드에 박지 않고도** 저절로 조용해진다. 같은 기간에 함께 실패하는 **나머지 여섯 자리**도
같은 원리로 고친다. 화면의 신선도 띠도 **같은 판정 한 벌**을 쓴다(M1).

## 1. 문제 — 실측

### 1-1. 시즌 도중에도 3일 넘게 빈다

실행 슬롯은 JST 07:00 · 08:30 · 14:00 · 15:30 · 23:30 · 01:00 이고(`daily.yml`),
**그날 경기는 23:30 실행만 받는다**(`JST_TODAY_FROM_HOUR = 22`). 마지막 경기일을 `L`,
다음 경기일을 `N` 이라 하면, 그 사이 실행의 「데이터 나이」는 최대 `N − L` 이다.
`freshness.ts` 는 `나이 > 2` 에서 실패하므로 **`N − L ≥ 3` 인 구간마다 `N − L − 2` 일 동안 실패한다.**

보유 완결 8시즌(2018~2025) · 로컬 DB · 경기일 1,547개 전수:

| 종류 | 구간 수 | 길이 |
|---|---|---|
| 정규시즌 종료 → CS | 8시즌 중 6 | 3~6일 |
| CS → 일본시리즈 | 8시즌 전부 | 5~8일 |
| 교류전 휴식(6월) | 4 | 3~5일 |
| 2021 올림픽 휴식 | 1 | **27일** |
| 그 밖(CS 내부 2 · 일본시리즈 내부 1 · 2020 정규 막바지 1) | 4 | 3일 |
| **합** | **23** | 시즌당 실패일 합 **4~35일** |

오프시즌(일본시리즈 마지막 경기 → 다음 개막)은 **118~240일**, 2020(코로나)을 빼면 **118~151일**이다.

⚠**수집 기록 153건(2026-08-15~09-11)에 `game-lag` 은 0건이다.** 휴식을 **한 번도 안 겪었다**는 뜻이지
안전하다는 증거가 아니다.

### 1-2. 같은 기간에 실패하는 자리가 일곱 곳이다

전부 `collect` 잡을 실패시킨다 → 배포 단계(`if: success()`)가 막힌다 → 하트비트가 6시간마다 메일을 보낸다.

| # | 자리 | 무엇이 울리나 | 처음 울릴 때 | 근거 |
|---|---|---|---|---|
| 1 | `freshness.ts` `game-lag` | 최신 경기 나이 > 2일 | **10월 초**(정규→CS) | **실측** 23구간 |
| 2 | `freshness.ts` `starters-lag` | 予告先発 행의 `MAX(fetched_at)` 이 2일보다 오래됨. **「試合が予定されていません」 페이지는 행을 안 남기므로**(`load-starters.ts:98`) 경기가 없으면 맥박이 멈춘다 | **10월 초** | 코드 판독 |
| 3 | `freshness.ts` `career-lag` | 「못 받은 선수의 마지막 출장일」이 4일보다 오래됨. 출장일은 **대회를 가리지 않는데**, 재취득 선정식(`emit-stale-player-ids.ts:139`)은 **정규시즌만** 본다 → CS·일본시리즈 출장자는 다시 받을 이유가 없는데 「못 받은 선수」로 영영 남는다 | **CS 첫 경기 약 5일 뒤** | 코드 판독(시험으로 재현한다 · §7) |
| 4 | `freshness.ts` `starters-behind` | 다음 경기일(`upcoming_game`)이 오늘인데 예고가 그 날짜에 못 미침. **월간 일정은 치러지지 않은 예비 경기를 계속 싣는다** | 일본시리즈 예비일 | **실측**: 2025년 11월 일정에 11/1·11/2 「ソフトバンク − 阪神」(6·7차전) 2행이 점수 링크 없이 남아 있다 · 시리즈는 10/30 에 끝났다 |
| 5 | `load-upcoming.ts` 빈 달 가드 | 아카이브에 있는 달이 **경기 행 0** 이면 「마크업이 바뀌었다」로 exit 1. 그런데 `discover.ts:89` 는 같은 모양을 **「경기가 없는 달(12~2월)」로 정상 처리**한다 — **두 가드의 전제가 반대다** | 경기 없는 달의 일정을 받은 날(12월~) | 코드 판독 · ⚠실물 12~2월 페이지는 **미측정** |
| 6 | 아카이버 `MonthlyScheduleCache.get` | 월간 일정이 404 면 예외 → 그날이 `ERROR` → exit 1 | 다음 시즌 일정 미공표 기간(1월~) | 코드 판독 · ⚠404 여부 **미측정** |
| 7 | `crosscheck.ts` 0명 게이트 | 새 시즌 공표표 폴더가 생겼는데 경기가 아직 없으면 대조 0명 → exit 1. 오류 문구가 스스로 「시즌이 아직 시작 전이다」를 원인으로 적는다 | 1~3월 | 코드 판독 · 미측정 |

### 1-3. 고치면 드러나는 여덟 번째 — 화면 띠

지금은 수집이 실패하면 배포가 막히므로 화면의 「更新が止まっています」(`isStale` · `lagDays > 3`)가
**실제 배포물에 나간 적이 사실상 없다.** §1-2 를 고쳐 휴식 중에도 배포가 돌기 시작하면,
**4일 이상 휴식하는 날마다 전 화면이 「取得に失敗している可能性があります」라고 말한다.**
`packages/web/test/stale-verdict.test.ts` 의 「경보 임계가 띠 임계보다 엄격하다」가 막으려던
**「화면은 멈췄다는데 수집 로그는 正常」**이 그대로 생긴다. → **띠도 같은 판정으로 바꾼다(D9).**

## 3. 용어와 실측 근거

| 용어 | 정의 |
|---|---|
| **예고** | 予告先発 페이지가 날짜 `D` 에 구단 `T` 의 선발을 공표했다 = `probable_pitcher` 에 `(game_date=D, team_code=T)` 행이 있다. **선발 이름이 미정(`player_id IS NULL`)인 행도 예고로 센다** — 경기가 열린다는 공표는 같다 |
| **휴식 공표** | 予告先発 페이지가 날짜 `D` 에 「試合が予定されていません」이라고 적었다. 파서가 이미 읽는다(`parseAnnouncedStarters` → `noGamesScheduled: true` · **`monthDay` 도 함께 준다**) |
| **받았다** | `game` 에 날짜 `D` 이고 `home_code = T` 또는 `away_code = T` 인 행이 있다. **상태를 가리지 않는다**(`played` · `notPlayed`) |
| **못 받은 경기** | 예고가 있는데 받지 않은 `(D, T)` 중 `today − LOOKBACK_DAYS ≤ D ≤ today − grace` 인 것 |

**실측(CI 최신 DB · 2026-09-11 · 예고 254행 · 2026-08-16~09-11)**
- 예고가 있는데 받지 않은 `(D, T)`(`D ≤ today − 2`): **0건** → 이 규칙은 지금까지 헛경보를 낼 자리가 없었다.
- 그 기간 `game` 행 **124건 중 124건**이 양 구단 예고를 가졌다 → 증거가 빠진 경기가 없다.
- 그 기간 중지 경기 **5건 중 5건**이 예고를 가졌고 `notPlayed` 행이 있다 → 중지를 「받았다」로 올바르게 센다.
- ⚠**전부 정규시즌이다.** CS·일본시리즈의 예고는 **안 쟀다**(§6 P3).

## 4. 설계

### D1. 새 축 `game-missed` — 「받았어야 할 경기를 못 받았다」

```
missed = { (D, T) | 예고(D, T) ∧ ¬받았다(D, T) ∧ today − LOOKBACK_DAYS ≤ D ≤ today − grace }
missed ≠ ∅  →  staleReasons 에 "game-missed"
```

- `grace` = 감시 `staleDays`(워크플로 인자 **2**) · 화면 `STALE_AFTER_DAYS`(**3**). 날짜 차는 JST 달력일.
- `LOOKBACK_DAYS = 30`. **`MAX_CATCHUP_DAYS`(7)보다 길게 둔다** — 7일을 넘긴 누락은 자동으로
  메워지지 않으므로 **영구 결손이 된 뒤에도 한 달은 계속 울려야** 사람이 안다. 무한으로 두지 않는 이유는
  같은 행이 영원히 울리면 아무도 안 보게 되기 때문이다.
- **옛 규칙과 같은 엄격함이다(연속 경기 기간).** 옛 규칙: `today − L > 2`. `D = L + 1` 을 못 받았다면
  `today − D ≥ 2` 에서 울린다 — 새 규칙의 `D ≤ today − 2` 와 같다.
- **옛 규칙보다 강한 점**: 구단 단위다. 6경기 중 1경기만 빠져도 잡는다(옛 규칙은 `MAX(game_date)` 만 봐서 못 잡았다).
- 휴식·오프시즌에는 예고가 없으므로 **아무 날짜도 박지 않고** 조용하다.

### D2. `game-lag` 은 백스톱으로 남긴다

```
age = today − MAX(game_date WHERE status='played')
seasonOver(최신 시즌) = false 이면  age > 45   → "game-lag"
seasonOver(최신 시즌) = true  이면  age > 200  → "game-lag"
```

- **목적은 이중 침묵이다** — 예고 파서와 월간 일정이 **동시에** 조용히 고장 나면 D1 은 증거가 없어 못 잡는다.
- 45 = 시즌 중 최장 실측 휴식 27일(2021 올림픽) + 여유. 200 = 오프시즌 실측 118~151일 + 여유.
- ⚠**2020 형 해(개막이 6월로 밀림 · 오프시즌 240일)에는 약 40일 동안 울린다.** 안전한 쪽의 틀림이고
  그런 해에는 사람이 알아야 할 일이기도 하다. 인자로 올릴 수 있게 둔다.
- `seasonOver` 는 **화면이 이미 쓰는 `seasonIsOver` 한 벌**이다(D10 에서 `store` 로 옮긴다).
- 키 `game-lag` 과 화면 문구 「試合が古い」는 그대로다 — 옛 기록 줄도 같은 뜻으로 읽힌다.

### D3. 予告先発 맥박을 경기와 떼어 놓는다 — 새 표 `starters_fetch`

```sql
CREATE TABLE starters_fetch (
  fetched_date TEXT PRIMARY KEY,          -- 아카이브 파일 이름의 날짜(JST)
  game_date    TEXT,                      -- 페이지가 말한 날짜. 연도를 못 정하면 NULL
  no_games     INTEGER NOT NULL CHECK (no_games IN (0, 1)),
  source_url   TEXT NOT NULL,
  fetched_at   TEXT NOT NULL              -- 사이드카(meta.json)의 취득 시각(M4)
);
```

- `load-starters.ts` 가 **아카이브의 모든 予告先発 파일**마다 한 행을 upsert 한다 — **휴식 공표 페이지 포함.**
  지금 `continue` 로 버리는 자리(98행)가 행을 남기게 된다.
- `starters-lag` 은 이 표의 `MAX(fetched_at)` 으로 잰다 → **경기 유무와 무관한 맥박.**
- 파서가 실패한 파일은 행을 안 남긴다(지금처럼 `failed` 로 센다) — 「받았다」와 「읽었다」를 섞지 않는다.
- `revision` 은 두지 않는다 — 날짜마다 **마지막 취득이 덮는** 표라 판(版)이 성립하지 않는다.
  `packages/store/test/provenance.test.ts` 의 면제 목록에 **사유와 함께** 넣는다.

### D4. `starters-behind` 는 NPB 가 「그날은 없다」고 하면 쉰다

기존 조건(`nextGameDay ≤ today ∧ starters.latest < nextGameDay`)에 **둘을 더한다**:

- `starters_fetch` 에 `game_date = nextGameDay ∧ no_games = 1` 이 있으면 울리지 않는다 — **예비 경기 날의 1차 근거.**
- `seasonOver(최신 시즌)` 이면 울리지 않는다 — 1차 근거가 없을 때(§6 P4)의 **2차 가드.**

### D5. `career-lag` 의 출장은 정규시즌만 센다

- `freshness.ts` 의 `appearance` CTE 에 `g.competition = 'regular'` 을 더한다.
- ⚠**그 조건을 두 파일에 따로 쓰지 않는다**(M1). `@bb-app/store` 가
  `CAREER_PAGE_COMPETITION = "regular"` 을 내보내고 `emit-stale-player-ids.ts` 와 `freshness.ts` 가 둘 다 쓴다.
  근거는 기존 주석 그대로다: 「年度別成績 표가 정규시즌이기 때문이다」(`emit-stale-player-ids.ts:104`).

### D6. 경기 없는 달의 일정은 실패가 아니다 — 두 가드의 전제를 하나로

- 파서가 **날짜 행 수**를 한 벌로 센다: `@bb-app/parser` 가 `scheduleDateRowCount(html)` 을 내보내고
  (`<tr … id="dateMMDD">` · `parseUpcoming` 의 `ROW` 와 같은 앵커), `parseUpcoming` 결과에 `dateRows` 를 더한다.
- `load-upcoming.ts`: 「경기 행 0」인 달은
  - `dateRows > 0` → **경기가 없는 달**이다. 지우고 다시 넣기를 그대로 하고, 「경기가 없는 달 N개」를 보고한다.
  - `dateRows = 0` → 지금처럼 `ScheduleShapeError`(M7 · 기존 일정을 지우지 않고 멈춘다).
- `packages/archiver/src/discover.ts` 의 자체 `DATE_ROW` 도 **같은 함수로 바꾼다**(M1).
- ⚠**지금 두 정규식은 너그러운 정도가 다르다** — `discover.ts:58` 은 `\sid=["']date\d{4}["']`(홑·곁따옴표),
  `upcoming.ts:45` 는 `id="date(\d{4})"`(곁따옴표만). 합칠 때 **좁은 쪽으로 맞추면** 따옴표만 바뀐 멀쩡한
  페이지가 「날짜 행 0」→ `ScheduleShapeError` 가 된다. **넓은 쪽(`discover.ts`)으로 맞추고**
  `parseUpcoming` 의 행 분할도 같은 앵커를 쓰게 한다.

### D7. 월간 일정 404 는 「미공표」다

- `MonthlyScheduleCache.get`: 응답이 **HTTP 404** 이면 예외 대신 **빈 목록**을 돌려주고 「미공표」로 표시한다.
  **404 가 아닌 실패**(5xx · 네트워크 · 본문 없음)는 지금처럼 예외다.
- `cli.ts` 는 그날을 `ERROR` 로 세지 않고 한 줄로 말한다: `YYYY-MM-DD 월간 일정 미공표(HTTP 404) — 경기 0건으로 본다`.
- ⚠**시즌 중 URL 이 바뀌어 404 가 계속되는 경우**: 경기를 하나도 못 찾지만 **예고는 계속 들어오므로
  D1 이 `grace` 일 안에 잡는다.** 이 안전이 D1 에 기대고 있다는 것을 코드 주석에 적는다.

### D8. 공표표 대조: 「양쪽 다 비었다」와 「안 쟀다」를 가른다

`crosscheck.ts` 가 대조 선수 0명일 때:

| 읽은 공표 페이지 | 공표표의 선수 행 | 우리 쪽 선수 행 | 판정 |
|---|---|---|---|
| 0장 | — | — | **exit 1**(못 읽었다 · 지금과 같음) |
| 1장 이상 | 0 | 0 | **exit 0** · 「대조할 성적이 양쪽 다 없다(시즌 전)」 |
| 1장 이상 | 그 밖 | 그 밖 | **exit 1**(지금과 같음) |

- 판정은 순수 함수 `zeroComparisonVerdict({ pagesRead, publishedRows, ourRows })` 로 뺀다.

### D9. 화면 띠는 같은 판정을 쓴다

- `Freshness` 에 `missedGames: number` 를 더한다 — 빌드 시점(`builtOn`)에 **D1 과 같은 증거 함수**를
  `grace = STALE_AFTER_DAYS` 로 부른 결과의 개수다.
- `isStale(f)` = `latestGameDate === null` ∨ `missedGames > 0` ∨ **D2 백스톱**(`lagDays` · `seasonOver`).
- 「경보 임계(2) < 띠 임계(3)」 시험은 그대로 둔다 — 뜻이 「나이」에서 「유예」로 바뀔 뿐 순서는 같다.
- **백스톱 수치(45 · 200)는 감시와 띠가 한 벌을 쓴다**(`collection-verdict.ts` 의 상수). 둘이 같은 날 울리는 것은
  괜찮다 — 감시가 실패하면 그날 배포가 막히므로 띠가 먼저 울 수 없다.
- 「終了したシーズンです」 갈래(`pastSeason ∨ seasonOver`)는 그대로다.

### D10. 판정은 한 벌이다 — 배치

| 무엇 | 어디 | 성격 |
|---|---|---|
| 증거 수집(SQL) | **`packages/store/src/collection-evidence.ts`** — `collectionEvidence(raw, today, lookbackDays)` | 예고·받음·휴식 공표·맥박·최신 경기·최신 시즌 |
| `seasonIsOver` · `japanSeriesDecided` | **`packages/web/src/query.ts` → `packages/store`** 로 옮긴다. web 은 가져다 쓴다 | SQL |
| 판정(순수) | **`packages/domain/src/collection-verdict.ts`** — `collectionVerdict(input)` · `STALE_REASON_KEYS` | 시계·DB 없음(M6) |
| 감시 셸 | `scripts/freshness.ts` — 증거 → 판정 → 출력·JSONL·종료 코드 | 얇게 |
| 화면 | `packages/web/src/site.ts` · `layout.ts` — 같은 증거·판정 | |

- `raw` 는 `node:sqlite` 의 `DatabaseSync` 다(`Db.raw` 와 `freshness.ts` 의 `new DatabaseSync()` 가 둘 다 맞는다).
- ⚠`stale-verdict.test.ts` 의 「감시가 미는 키 전부에 화면 문구가 있다」는 지금 **`freshness.ts` 소스에서
  `staleReasons.push("…")` 를 정규식으로 긁는다.** 판정이 도메인으로 가면 그 문자열이 사라져
  **「키를 5개 미만 찾았다」로 떨어진다** → 키 목록을 `STALE_REASON_KEYS` 에서 읽게 바꾼다.
- 새 키 `game-missed` 의 화면 문구: **「未取得の試合」**.

### D11. 통과한 이유를 남긴다 — `period`

- 판정이 `period` 를 함께 낸다: `"games"`(오늘±1일에 예고·경기가 있다) · `"rest"`(휴식 공표가 있거나 예고가 없고 시즌 중) ·
  `"offseason"`(`seasonOver` 이고 예고 없음).
- `freshness.ts` 가 콘솔 한 줄과 JSONL 필드 `period` · `missedGames`(개수)로 남긴다.
- ⚠**종료 코드에 쓰지 않는다** — 정보다. 「휴식이라 통과했다」와 「경기를 받아서 통과했다」를
  **나중에 구별하려고** 남긴다. 수집 로그 화면은 이번에 안 바꾼다.

- **시즌 종료 판정 + 만료일**(사용자 질문의 2안) — 일본시리즈가 끝나야 참이 되므로 10월의 두 휴식을 못 덮는다.

- **오프시즌 수동 정지**(4안) — 켜는 것을 잊으면 개막 뒤 조용히 멈춘다. 10월 경보는 남는다.
- **월간 일정의 「앞으로의 경기」를 「있어야 할 경기」로 쓰기** — **예비 경기가 링크 없이 남는다**(§1-2 #4 실측).
  반대 방향(「치러짐 표시가 있는데 우리에게 없다」 · `load-upcoming.ts` 의 `orphans`)은 쓸 수 있지만
  **표를 새로 만들어야 하고**, 예고 증거가 이미 **124/124** 로 덮는다. `orphans` 로그는 그대로 둔다.
- **달력 날짜를 코드에 박기**(「3월 20일부터 감시」) — 2020 처럼 개막이 밀리면 틀리고, **NPB 공표가 이미 있다.**
