# 최애 구단 — 설계

2026-08-18 · 상태: 승인 대기

## 왜 지금인가

주 내비게이션은 7항목(`試合 一覧 順位 対戦 比較 他大会 記録`)인데 **구단이 없다.**
구단 페이지(`teams/<코드>.html`)는 이미 두툼한데(チーム成績·月別·直近·日程·打者·投手·対戦成績)
**순위표에서 팀명을 눌러야만** 닿는다. 팬이 가장 자주 볼 화면으로 가는 길이 가장 멀다.

즐겨찾기 장치는 이미 있지만(`state.favs`, localStorage) **선수 전용**이고 구단에는 없다.

## 범위

1. 우승 경쟁 계산 한 벌 — `packages/aggregate/src/race.ts`
2. 구단 페이지 승격 — 「지금 이 팀」 요약 띠 + 이동 · 이 팀의 연속 기록/기록 근접
3. 구단 목록 화면 `teams.html` + 내비 첫 항목 `球団`
4. 최애 구단 지정(클라이언트 상태)
5. 시험

### 범위 밖 (이번에 안 한다)

- **CS(클라이맥스) 진출 라인** — 3위 조건은 규칙이 또 다르다(게임차 어드밴티지 등).
  우승 판정을 정확히 세운 뒤에 얹는다.
- **이 팀 선수의 리그 순위 요약** — 사용자가 이번 범위에서 뺐다. 이동 버튼으로 대신한다.
- **A(수치 정당성)·B(추가 지표)·C(독창 지표)** — 별도 스펙으로 각각 한 바퀴.

## 1. 우승 경쟁 계산 — `aggregate/src/race.ts`

### 왜 한 벌인가

구단 페이지의 요약 띠와 순위 화면이 **같은 함수**를 부른다(M1).
이 저장소는 「같은 값이 화면마다 다르다」를 여러 번 밟았다 — 2026-08-18 감사에서만
규정 판정이 그 형태로 두 번 나왔다(순위표는 「打率21位」, 같은 선수 페이지는 「順位がつきません」).

### 직접대결 잔여는 **규칙에서 나온다** — 예정 일정을 쓰지 않는다

처음에는 `upcoming_game`(공표된 예정)으로 직접대결 잔여를 세려 했다. **그건 틀린 설계였다.**

실측(아카이브 전수):

```
2018·2019·2021~2025   리그 내 30쌍 전부 25   교류전 36쌍 전부 3    예외 0건
2020                  리그 내 30쌍 전부 24   교류전 0쌍            24×5 = 120 ✓
2026(진행 중)          리그 내 14~21          교류전 36쌍 전부 3    (6월에 끝남)
```

대전 수는 **규칙으로 고정**이고 완결 7시즌에서 값의 종류가 하나씩뿐이다.
그러므로

```
직접대결 잔여(A,B) = 규정 대전수(A,B) − 이미 치른 A:B 경기 수

규정 대전수(A,B) = A 와 B 가 같은 리그면 「리그내 대전수」, 아니면 「교류전 대전수」
```

이고, 우리가 **확실히 아는 것**만 쓴다. 덤으로 `Σ_B 잔여(A,B) = regularSeasonGames − 소화` 가
**자동으로 성립**해서 별도 정합성 검사가 필요 없다.

⚠**예정 일정은 못 믿는다**(같은 실측): 일정 페이지의 행은 `치름 + 중지 + 미실시` 이고,
中止 재편성 상태에 따라 미실시 합계가 실제 잔여와 ±3 어긋난다
(中日 +3 · 阪神 +1 · 広島 −1).

→ **예정 일정(`upcoming_game`)은 「다음 경기가 언제·어디서·누구와」에만 쓴다.**
   그건 **한 경기의 사실**이라 합계가 어긋나도 그 한 줄은 맞다.
   **세는 일에는 쓰지 않는다** — 잔여도 직접대결도 전부 규칙과 치른 기록에서 나온다.

### 규정 대전수는 시즌마다 유도한다 — 하드코딩하지 않는다

2020이 그 이유다(교류전 미개최 + 리그 내 24). `regularSeasonGames` 를 시즌별 표로 바꿨던 것과 같은 함정.

```
교류전 대전수 = 그 시즌 교류전 쌍의 최대 관측값
리그내 대전수 = (regularSeasonGames(시즌) − 교류전 대전수 × 6) / 5
```

⚠**유도 결과가 양의 정수가 아니면 판정하지 않는다**(`null`).
교류전이 진행 중인 5~6월에는 관측값이 1~2라 `(143−6)/5 = 27.4` 처럼 정수가 안 나온다 —
그게 **「아직 모른다」의 신호**가 된다. 143 시즌에서 정수가 나오는 것은 교류전이 3일 때뿐이고,
120 시즌에서는 0일 때뿐이다. **검산이 공짜로 붙는다.**

⚠**추가 안전장치**: 어떤 쌍이라도 유도된 상수를 이미 넘겼으면 유도가 틀린 것이므로 판정하지 않는다.

### 출력

팀마다:

| 필드 | 뜻 | 식 |
|---|---|---|
| `remaining` | 잔여 경기 | `regularSeasonGames(시즌) − 소화` |
| `h2hLeft` | 상대별 잔여 | `규정 대전수 − 치른 수` |
| `selfPossible` | 자력우승 가능 | 아래 |
| `magic` | 매직 넘버 | 아래. 조건 미충족이면 `null` |
| `eliminated` | 우승 가능성 소멸 | 아래 |
| `basis` | 판정의 근거 상태 | `"confirmed"` \| `"unknown"` |

**승률은 `勝 / (勝 + 敗)`** — NPB는 무승부를 분모에서 뺀다.

**자력우승 가능**: A가 잔여를 전승했을 때

- A 최종 승률 = `(w + R) / (w + R + l)`
- B가 낼 수 있는 최대 승률 = `(w' + R' − h) / (w' + l' + R')` — A와의 잔여 `h` 는 B가 전패한다
- 모든 B에 대해 **A ≥ B** 이면 자력 가능

⚠**동률을 「가능성 있음」에 넣는다**(일본 통례). 동률이면 규정에 따른 결정이 남는다는 것을 화면에 적는다.

**우승 가능성 소멸**: 어떤 B가 **잔여를 전패해도** A의 최선을 넘으면 소멸

- `w' / (w' + l' + R') > (w + R) / (w + R + l)` 인 B 가 하나라도 있으면 `eliminated`

**매직 넘버**: **다른 모든 팀의 자력이 소멸**했을 때만 낸다(그것이 점등 조건이다).

- `magic = max over B≠A ( (w' + R') − w ) + 1`

⚠**매직만 승수식이고 나머지는 승률**이다. NPB 순위는 승률로 정하는데 매직은 관례가 승수식이다.
그 차이를 화면 각주에 적는다(M3 — 기준이 곧 값이다).

### 화면이 말하는 다섯 상태

```
自力優勝の可能性あり
マジック 12
自力優勝消滅
優勝の可能性なし
まだ判定できません（今季の対戦数が確定していません）
```

⚠**마지막 상태를 숨기지 않는다**(M11·M12). 왜 못 정하는지도 함께 쓴다.

## 2. 구단 페이지 승격

`teams/<코드>.html` 맨 위(기존 `チーム成績` 앞)에 `b-tnow` 구획을 새로 둔다.

```
┌──────────────────────────────────────────────┐
│ 2位  59-46-1  .562(105試合)  首位と3.5ゲーム差  残り37試合 │
│ 直近10  6-4-0                                        │
│ 次の試合  8/18(月) 18:00  vs 広島 @ 甲子園            │
│   予告先発  村上 ─ 大瀬良                             │
│ 自力優勝の可能性  あり                                │
└──────────────────────────────────────────────┘
  [予告先発を見る] [順位表で見る] [選手一覧] [日程]
```

⚠**모든 비율에 분모를 붙인다**(M2). 승률에는 `(勝+敗)`, 최근10에는 실제 경기 수.
⚠**다음 경기가 없으면**(시즌 종료·경기 없는 날) 그 줄을 지우지 않고 그렇게 말한다(M12).
⚠**予告先発이 아직 없으면** 「発表待ち」다 — 「投手なし」가 아니다(M11).

### 이 팀의 연속 기록 · 기록 근접

홈 화면의 `続いている記録`·`記録に近づいている` 을 **팀으로 거른다.**
`HomeStreak`·`HomeMilestone` 이 이미 `teamCode` 를 들고 있어 배열 필터 한 줄이다.

⚠**0건이면 구획을 지우지 않고 「없다」고 말한다**(M12).

### 이동 버튼이 가리킬 앵커 — 없는 것은 만든다

실측: `starters.html#pn-starters-<카드>` 는 **이미 있다**. 一覧·順位에는 **팀별 앵커가 없다**(리그 단위만).

- `players.html` 의 구단별 구획에 `id="hi-<코드>"` 를 더한다
- `ranking.html` 의 순위표 행에 `id="stand-<코드>"` 를 더한다

⚠**id 는 한 벌에서 만든다**(M1). 빌드의 링크 검사가 깨진 앵커와 ARIA 참조를 잡는다.

## 4. 최애 구단 지정

`state.favTeam` — **문자열 하나**다. 「가장 첫탭」이 하나여야 하므로 복수를 두지 않는다.
기존 선수 즐겨찾기(`state.favs`)는 건드리지 않는다 — 다른 개념이다.

클라이언트가 하는 일은 셋뿐이다.

1. 내비 첫 항목의 라벨(`球団` → `阪神`)과 링크(`teams.html` → `teams/t.html`)를 교체
2. 지정 버튼의 `aria-pressed` 반영
3. 지정·해제를 즉시 반영

⚠**CSP 가 인라인 스크립트를 막으므로**(`script-src 'self'` 를 우리가 닫아 뒀다) 교체는
외부 스크립트가 로드된 뒤에 일어난다 — **한 프레임 깜빡임이 있다.**
그 전에 눌러도 구단 목록으로 가므로 길이 끊기지는 않는다.
없애려면 CSP 를 열어야 하는데 그 대가가 더 크다.

⚠**JS 가 없으면** 첫 탭은 `球団` 인 채로 목록으로 간다(§0-1).
아무것도 안 깨지고, **오히려 지금 없는 「구단으로 가는 길」이 생긴다.**

⚠**저장은 이 브라우저에만 남는다.** 계정이 없는 서비스라 그게 전부다 — 화면이 그렇게 말한다.

## 5. 시험

### `race.ts` 단위

- 규정 대전수 유도: 143 시즌 → 25/3 · **120 시즌(2020) → 24/0**
- 교류전 진행 중(관측 1~2) → `basis="unknown"` · `selfPossible`·`magic` 은 `null`
- 어떤 쌍이 유도 상수를 넘으면 → `unknown`
- 자력 판정: 동률을 「가능성 있음」에 넣는가
- 소멸 판정: 상대가 전패해도 못 넘는 경우
- 매직: **다른 모든 팀의 자력이 살아 있으면 `null`**(점등 조건)

### 완결 시즌 실데이터 대조 — 이 계산의 진짜 검산

2018·2019·2021~2025 각 시즌에서 **최종 1위 팀이 시즌 마지막 시점에 우승 확정으로 판정되는가.**
그리고 최종 1위가 아닌 팀은 마지막에 전부 `eliminated` 인가.

### 화면

- 요약 띠의 모든 비율에 분모가 붙는가(M2)
- 판정 불가일 때 이유가 함께 나오는가
- 연속 기록·기록 근접이 0건이어도 구획이 남는가(M12)
- 이동 버튼의 앵커가 실재하는가(빌드 링크 검사)

### 클라이언트

- 지정·해제가 저장되고 다시 열어도 살아 있는가
- 내비 첫 항목이 교체되는가
- **서버 출력에 `球団` 항목이 있는가**(JS 없는 경우의 §0-1)

⚠**새 시험은 전부 「고치기 전 코드에서 실패하는가」를 확인한 뒤 채택한다**(작업규칙 9).
