## 0. ⚠사용자가 고른 것 — 다시 고르지 마라

| # | 물은 것 | **정해진 것** |
|---|---|---|
| ⑴ | 세 안 중 방향 | **C 기반 + A·B 에서 빌려온다** |
| ⑵ | 애니메이션 강도 | **진입 연출까지**(막대 차오름 등) |

⚠**⑵ 는 내 추천(「상태가 변할 때만」)보다 한 단계 위다.** 사용자가 의도적으로 올렸다.
**줄이는 방향으로 되돌리지 마라.**

## 1. 왜 C 가 바탕인가

세 불만(**딱딱하다 · 여백이 투박하다 · 애니메이션이 거의 없다**)에 **전부** 답하는 유일한 안이고,
수치가 가장 좋다(실측 · 현행 대비):

| | 현행 | C |
|---|---|---|
| 390px 첫 화면 가로 스크롤 영역 | **4** | **1** |
| 순위표 폭 @1280(눈의 횡단거리) | 1,136px | **742px (−35%)** |
| 28×28 미만 조작 대상(홈) | **133 / 152** | **0 / 170** |
| `tr`·`td` 에 걸린 트랜지션(홈) | 42 | **0** |
| 순위표 행 높이 @390 | 60.4px | **58.9px**(줄었다) |

⚠**C 담당이 내 브리프를 두 번 이겼고 그 판단이 옳았다.**
⑴ 내가 「세그먼티드 컨트롤」을 지시했는데 HIG 원문이 **「5개 이하 · 동일 폭」**을 요구해
후보 셋(시즌 9 · 章 7 · 내비 10)이 전부 어긴다며 **거부**했다 —
「골랐다면 HIG 를 따른 게 아니라 **HIG 처럼 보이게 한 것**」.
⑵ 내가 「행마다 전환을 걸면 순위 화면이 무너진다」고 경고했는데,
**현행 CSS 의 `tbody tr{transition:background}` 가 이미 순위 화면 4,450행에 걸려 있다.**
**걱정한 상태가 이미 현실이었다.**

## 2. 무엇을 빌려오는가 — 출처와 이유

| 빌려올 것 | 어디서 | 왜 |
|---|---|---|
| **모바일 크롬 절약** | **A** | C 의 최대 약점이 **고정 크롬 87px**(현행 46)이다. A 는 내비를 **버튼**으로, 시즌 띠를 **드롭다운**으로 접어 첫 화면을 아꼈다. ⚠**C 의 세로 레일은 유지한다** — 그건 A 에 없는 강점이다 |
| **괘선 굵기의 위계 · 활자 대비** | **B** | 「연감」의 성격이 이 제품의 **독창성**(§0 제약6)이다. C 는 깔끔하지만 성격이 옅다. ⚠**선을 되살리는 게 아니라 굵기에 뜻을 주는 것**이다 |
| **표 열 묶음** | **B·C 공통** | 둘이 독립으로 같은 답에 왔다(`成績/勢い/この先` · `勝敗/得失点/近況/見通し`). **눈의 횡단거리**를 줄이는 핵심 |
| **「이 표는 옆으로 흐른다」고 말하기** | **셋 공통** | 세 안이 전부 같은 답에 왔다. **남은 가로 스크롤 1개는 스스로 그렇다고 말한다** |

⚠**목차는 C 의 세로 레일을 쓴다**(B 의 `目次` 가 아니라). 레일은 **상시 남고 현재 위치도 말한다** —
B 의 목차는 한 번 보고 마는데 **모바일 첫 화면 290px** 을 매번 낸다(B 담당 자신의 지적).

## 3. 모션 — ⑵ 를 따르되 재생 조건을 정한다

**넣는다**: 상태 전환(탭·툴팁·팝오버·시트) + **진입 연출**(승패 막대·득실 막대 차오름).

⚠**C 담당이 스스로 적은 우려**: 「막대 차오름이 **매번 재생**되는 것이 HIG 의
*don't make people wait* 와 아슬아슬하다」. **없애지 않고 조건을 건다:**

- **뷰포트에 처음 들어올 때 1회**만 재생한다(`IntersectionObserver` · 재진입 시 재생 안 함).
- **`prefers-reduced-motion` 에서는 최종 상태로 즉시** 그린다. ⚠**분기를 나중에 붙이지 않는다.**
- ⚠**표 행·셀에는 트랜지션을 걸지 않는다.** 순위 화면이 42,703노드다.
  **모션은 조작층에만** 걸어 **표 크기와 무관한 고정 비용**으로 만든다(C 의 설계 그대로).

## 4. ⚠깨면 개악인 것 (감사 §5 를 여기 다시 못 박는다)

- **표 한 줄이 두 줄이 되면 안 된다.** 여백은 **위계를 만드는 데** 쓰고 **밀도를 깎는 데** 쓰지 않는다.
- **각주(긴 설명문)를 지우지 않는다** — 그건 이 사이트의 정직함이다. **읽기 쉽게** 만드는 것이 과제다.
- **색은 도메인에서 뽑는다**(감청·주황·크림·구단색). ⚠**iOS 기본 파랑으로 수렴하면
  「AI틱함」 회피 목록을 정면으로 어긴다.**
- **상태를 색만으로 말하지 않는다** · **키보드** · **WCAG AA** · **M12 빈 상태 4종**.
- **`prefers-reduced-motion`** 분기.

## 5. ⚠미해결 — 착수 전에 답해야 하는 것

1. **`ranking.html`(42,703노드)에 이 CSS 를 얹어 본 적이 없다.** C 담당이
   「개선폭 ~285요소는 **산수 추정이지 실측이 아니다**」라고 신고했다.
   ⚠**브리프가 「거기서 먼저 재고 전역에 얹으라」고 했는데 홈만 만들었다. 그 순서를 지켜라.**
2. **표 열 머리의 세로 고정을 C 가 포기했다** — `overflow-x:auto` 그릇이 세로 sticky 의 기준이 되어
   머리 행이 표 중간에 붙는다(Chromium 실측). 홈은 최장 12행이라 손해가 작지만
   **순위 화면의 긴 표에는 다른 해법이 필요하다.**
3. **모바일 고정 크롬 87px 을 A 의 방식으로 얼마나 줄일 수 있는가** — C 담당은
   「`position:fixed` 재구성이 필요한데 **미검증인 채로 넣지 않았다**」고 했다.
4. **시즌 그리드가 9년 기준**이다 — **드래프트 화면은 21시즌**이다(안 쟀다).
5. **1024~1079px 구간에 레일도 인라인 내비도 없다** — 의도된 동작이지만 그 폭이 제일 허전하다.
6. **좁은 화면에서 「어느 페이지에 있는지」가 안 보인다**(C 담당 지적).
7. **선수 페이지(블록 14개)에서 세로 레일이 성립하는지 모른다** — 홈 1장만 만들었다.
8. **Safari·Firefox 미확인** · **실기기·스크린리더 미확인** · **200% 확대·Dynamic Type 미확인**.

## 5-A. 서체 — **IBM Plex Sans JP + IBM Plex Sans** (사용자 결정 · 2026-09-07)

### ⚠먼저: 지금은 웹폰트가 **하나도 없다**

```
--f-body: "Yu Gothic","Hiragino Kaku Gothic ProN","Noto Sans JP","Meiryo",system-ui,sans-serif
--f-num:  "SFMono-Regular","Consolas","Menlo","Yu Gothic",monospace
```

전부 **시스템 폰트**다. 그래서 **Windows 는 Yu Gothic · Mac 은 Hiragino** 로 나오고
**OS 마다 얼굴이 다르다.** Windows 의 Yu Gothic 은 작은 크기에서 가늘어
**「딱딱하다」는 인상에 실제로 기여한다.** ⚠**숫자가 `Consolas`/`SFMono` 라 코드처럼 보이는 것**도
이 제품(숫자가 주역)에는 특히 나쁘다.

### 부분집합이 가능한가 — **가능하다**(실측)

배포물 HTML **9,392장 중 627장 표본**(태그·엔티티 제외 · **보이는 글자만**):

| | |
|---|---|
| **고유 글자** | **1,183자** |
| 漢字 | 941 |
| カタカナ | 79 |
| ASCII | 67 |
| ひらがな | 62 |

⚠**증가 곡선이 확실히 포화한다** — 62장 997자 → **10배인 620장에서 1,181자**.
전수로 가도 **1,300~1,600자** 선으로 본다(⚠**추정이다. 전수는 안 쟀다**).
→ 1,500자 WOFF2 는 **80~200 KB** 로 라틴 한 벌 수준이고 **9,624장에 한 번만 캐시**된다.

### 서빙 — **빌드 때 `dist` 의 실제 글자에서 부분집합을 만들어 자체 호스팅**

- 외부 의존을 늘리지 않는다(Google Fonts 를 쓰지 않는다).
- **추측이 아니라 산출물에서 유도**한다 — 이 프로젝트의 방식과 같다.
- ⚠**빌드마다 다시 만든다.** 새 선수의 희귀 한자가 들어오는데 부분집합이 낡으면
  **그 글자만 시스템 폰트로 떨어져 이름 중간에서 얼굴이 바뀐다.** 웹폰트가 없는 것보다 나쁘다.
- ⚠**OFL 라이선스 파일을 같이 실어야 한다.**

### ⚠착수 전에 반드시 확인할 것

1. **IBM Plex Sans JP 가 우리가 쓰는 한자 941자를 실제로 덮는가.**
   **덮지 못하는 글자를 목록으로 뽑아라.** 하나라도 빠지면 위의 「얼굴이 바뀌는」 문제가 난다.
   ⚠**커버리지를 확인하기 전에는 이 서체를 확정으로 쓰지 마라** — 대안은 Noto Sans JP 다.
2. **`font-feature-settings:"palt" 1`** 이 이미 켜져 있다. Plex JP 에서 `palt` 가 어떻게 도는지
   확인하라 — 안 도는 서체면 자간 설계가 달라진다.
3. **숫자는 `font-variant-numeric: tabular-nums`** 로 간다(등폭 코드 서체를 버린다).
   ⚠**표에서 자릿수가 흔들리지 않는지 실측하라.**
4. **가변 폰트인지 정적 웨이트인지**에 따라 파일 수가 달라진다.
   ⚠**Pages 배포 파일 상한 20,000 중 현재 9,624** 다.

## 5-B. 서체를 **고를 수 있게** 한다 (사용자 결정 · 2026-09-07)

**선택지 3종**. 화면 상단의 표시 설정(지금 테마가 있는 자리)에 붙인다.

| 표시 | 내용 | 비용 |
|---|---|---|
| **기본(システム)** | 지금 그대로 — 웹폰트를 **안 받는다** | 0 |
| **IBM Plex** ⭐**기본값** | Plex Sans JP + Plex Sans | 부분집합 1벌 |
| **Noto Sans JP** | Noto Sans JP + Noto Sans | 부분집합 1벌 |

⚠**기본값은 IBM Plex 다**(사용자가 고른 것). 「기본(システム)」은 **웹폰트를 원치 않는 사람의 탈출구**이지
초기 상태가 아니다. ⚠**이 해석이 틀렸으면 여기부터 고쳐라.**

- 저장은 기존 테마 설정과 같은 방식(브라우저 로컬)이다. **서버가 없다.**
- ⚠**고르지 않은 서체는 받지 않는다.** `<link rel=preload>` 를 전부 걸면 세 벌을 다 받는다.
- ⚠**전환할 때 글자가 튀는 것**(FOUT)을 어떻게 다룰지 정하라. `font-display` 값과
  전환 시 레이아웃 이동을 **실측**하라 — 표가 주역이라 자릿수가 흔들리면 치명적이다.

## 5-C. ⚠**누락을 검사로 막는다** (사용자 지적 · 2026-09-07)

> 「부분 집합은 좋은데, **누락없게 신경 써주고**」

⚠**옳은 지적이고, 나는 이것을 「위험」으로만 적어 뒀다. 위험은 검사가 아니다.**
누락이 나면 **그 글자만 시스템 폰트로 떨어져 이름 한가운데서 얼굴이 바뀐다** —
**웹폰트가 없는 것보다 나쁘다.** 그러므로 **빌드가 실패해야 한다**(M7 — 조용한 실패 금지).

### 검사 규칙

1. **부분집합은 전수에서 유도한다** — ⚠**내가 잰 1,183자는 9,392장 중 627장 표본이다.**
   **빌드는 전 페이지를 훑어야 한다.**
2. ⚠**정적 HTML 만으로는 부족하다.** 클라이언트가 만드는 글자(검색 결과 · JS 안의 문자열 ·
   `aria-label` 로만 나오는 말)는 HTML 본문에 안 나온다. **번들의 문자열도 훑어라.**
3. ⚠**부분집합은 원본에 없는 글자를 만들어 내지 못한다.** 그러므로 검사는 이것이다:

   > **(쓰이는 글자) ⊆ (그 서체의 cmap)** 이 아니면 **빌드를 실패시키고 빠진 글자를 전부 출력한다.**

   **서체마다** 검사한다 — Plex 가 덮는데 Noto 가 못 덮는(또는 반대) 글자가 있을 수 있다.
4. **시험으로 고정한다**(M3) — 뮤테이션으로 「한 글자를 빼면 빌드가 붉어지는가」를 확인하고 채택하라.

⚠**이 검사가 없으면 부분집합을 쓰지 마라.** 검사 없는 부분집합은
**「대개 맞는 화면」**이고, 이 프로젝트는 그것을 가장 나쁜 상태로 친다.

## 5-D. 서체를 씌워 봤다 — **깨지지 않는다**(실측 2026-09-08)

⚠**사용자 요청**: 「각 폰트를 적용했을 때 영역이나 박스, 텍스트가 깨지거나 정렬이 망가지진 않는지」.
**추측하지 않고 실제 배포물에 씌워서 쟀다.**

**대상**: 홈 · 선수 · 순위 × **390 / 1280** 두 폭. 행 합계 **2,981행**(보이는 것만).

| 지표 | IBM Plex | Noto Sans JP |
|---|---|---|
| **표 행이 두 줄 되는 것** | **0 / 2,981** | **0 / 2,981** |
| 가로 넘침 | **0**(변화 없음) | **0**(변화 없음) |
| 글자 잘림 | **0**(변화 없음) | **0**(변화 없음) |
| 행 높이(중앙) | **변화 0** | **변화 0** |
| 표 폭 @390 | ⚠**+16 ~ +33px** | ~0(−8 ~ +5) |
| 표 폭 @1280 | 0 | 0 |
| 페이지 높이 | −29 ~ +56 | −6 ~ +0 |

→ **둘 다 레이아웃을 깨지 않는다.** 유일한 실질 차이는 **IBM Plex 가 좁은 화면에서 표를 20~33px 넓힌다**는
것인데, 표가 자기 컨테이너 안에서 스크롤하므로 **가로 넘침은 0** 이다.

### ⚠⚠이 측정에 이르기까지 프로브가 **세 번** 틀렸고, 세 번 다 「깨짐 0」이라는 **거짓 통과**를 냈다

**그대로 보고했으면 근거 없는 안심을 준다. 다음 사람은 이 셋을 반드시 피해라:**

1. **정착 시간을 안 줘서** 빈 페이지를 재고 「행 0개 = 깨짐 없음」으로 읽었다.
2. ⚠**사이트 CSP 가 외부 폰트를 막는다**(아래 5-E). 그걸 모른 채 Google Fonts 를 주입했다.
3. ⚠**`unicode-range` 슬라이스는 그 글자가 실제로 그려질 때 받는다.** 측정용 요소를 만들자마자
   지워서 **폴백 폭을 재고 있었다.** → **`document.fonts.load()` 로 명시적으로 기다린 뒤 잰다.**

→ **최종 프로브는 적용을 먼저 증명한다**(로드된 face 수 + **같은 글자의 폭 변화**:
시스템 695px → Plex **690.64** / Noto **630.48**). **증명 안 되면 「측정 실패」로 찍고 0 으로 흘리지 않는다.**

### ⚠안 잰 것

- **Mac(Hiragino 기준)** 에서의 차이 — 여기는 Windows(Yu Gothic 기준)다.
- **우리가 만들 부분집합 자체** — 여기서는 Google 슬라이스로 쟀다. **글리프가 같아 지표는 같지만
  부분집합 파이프라인은 별개로 검증해야 한다.**
- **`palt` 상호작용** · **Safari·Firefox** · 나머지 화면들.

## 5-E. ⚠CSP 가 자체 호스팅을 **강제한다** (2026-09-08 발견)

배포물이 이 헤더를 건다(`dist/_headers` · `packages/web/src/site.ts`):

```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
img-src 'self' data:; font-src 'self'; connect-src 'self'; ...
```

⚠**`font-src 'self'`** — **자기 출처의 폰트만 허용한다.** Google Fonts 는 **프로덕션에서도 막힌다.**
(네트워크 문제가 아니다 — `curl` 은 HTTP 200 이었다.)

→ **§5-A 가 고른 자체 호스팅은 「선호」가 아니라 「유일한 길」이었다.** 결론은 안 바뀌고 **근거가 생겼다.**
⚠**CSP 를 완화해서 외부 폰트를 쓰는 길로 가지 마라** — 그 헤더는 이 사이트의 보안 경계다.

## 5-F. 부분집합을 실제로 만들었다 — ⚠**내 추정 둘이 빗나갔고 두 글자가 없다** (2026-09-08)

파이프라인 커밋 `72b7423`. **Node 만 쓴다**(`subset-font` + `fontverter` · **Python 0**).

### ⚠내 추정이 빗나간 곳 둘

| 내가 §5-A 에 적은 것 | 실측 |
|---|---|
| 「전수 추정 **1,300~1,600자**」 | **1,646자**(漢字 1,350) — **46자 넘겼다** |
| 「1,500자 WOFF2 는 **80~200 KB**」 | **JP 한 웨이트가 297 KiB** · **3웨이트 스택이 Plex 960 / Noto 814 KiB** |

⚠**크기 추정은 한 자리 틀렸다.** 로딩 전략(400 먼저 · 600/700 지연, 또는 웨이트 줄이기)을
**CSS 배선에서 정해야 한다.** 파일 수는 **+16장**(9,549 → 9,565 / 20,000 = 47.8%)이라 문제없다.

### ⚠⚠두 글자가 **네 서체 모두에 없다** — 지금 빌드는 종료코드 1 이다

```
U+25B8 "▸"   U+25C2 "◂"
```

출처는 `packages/web/src/assets.ts` 세 줄(`.pickfold>summary::after` · `.cmprow .win::after` ·
`.cmprow .vb.win::before`).

⚠**게이트가 의도대로 작동했다** — 조용히 Noto 로 바꾸지도, 예외 목록을 만들지도 않고 **빌드를 세웠다.**

**정한 것(2026-09-08)**: **`▸`→`▶`(U+25B6) · `◂`→`◀`(U+25C0)** 로 바꾼다.
실측으로 **plex-jp·noto-jp 둘 다 갖고 있다.** 같은 「채운 삼각형」 계열이라 뜻이 안 바뀐다.
⚠**대안도 있었다**(`▲▼△▽` · `›‹`) — 더 가벼운 표식을 원하면 `›‹` 다.
⚠**`▶` 는 `▸` 보다 크다. 바꾼 뒤 눈으로 확인하라.**

### ⚠OFL 예약 서체명 — **사람이 정해야 하는 법적 사항**

**IBM Plex 의 예약 서체명(Reserved Font Name)은 `"Plex"`** 다.
OFL §1 이 **「글리프를 지우는 것」도 Modified Version 으로 정의**하므로 **부분집합은 개변판**이고,
§3 이 개변판에 예약명 사용을 금한다. **벤더링한 원본은 개변하지 않아 무관하지만
`dist` 로 나가는 부분집합을 `@font-face` 에서 뭐라 부를지**가 걸린다.
(**Noto Sans JP 의 예약명은 `Noto` 가 아니라 `Source`** 라 걸리지 않는다 — 그 OFL 은 Source Han 계열이다.)

**기본값으로 정한 것**: 부분집합의 CSS 패밀리명에서 **`Plex` 를 빼고 `BN Sans` / `BN Sans JP`** 를 쓴다.
⚠**이건 안전한 쪽으로 고른 기본값이지 법률 판단이 아니다**(§2-5 와 같은 태도).
**Google Fonts 가 같은 서체의 부분집합을 원래 이름으로 서빙하는 것도 사실**이라 해석이 갈리는 자리다.
→ **사용자가 「원래 이름을 쓰자」고 하면 그때 바꾼다.**

### 좋았던 판단 — **텔레메트리를 피해 벤더링했다**

`@ibm/plex-sans-jp@2.0.0+` 가 **`postinstall: ibmtelemetry`** 를 단다.
⚠**그 스크립트는 `contents: write` + Cloudflare 배포 토큰이 도는 잡에서 실행된다.**
`scripts/test/install-scripts.test.ts` 의 기준(「무엇을 놓는지 적어라」)을 통과할 수 없다 —
**텔레메트리는 아무것도 안 놓고 IBM 으로 통계를 보낸다.**
→ **저장소 벤더링**(woff2 6장 + OFL · 7.2 MB). Noto 는 설치 스크립트 0개라 npm 고정.
⚠**낮은 판으로 내려가는 길은 실측으로 막혔다** — `@ibm/plex-sans-jp@1.0.0` 은 cmap 이 8,316자뿐이라
**`⚠`(U+26A0)을 못 덮는다**(그 글자는 화면에 실재한다).

### `tabular-nums` — 물음 자체가 바뀌었다

§5-A 3 은 「`tnum` 을 켠다」였는데, **`tnum` 기능은 Plex 양쪽과 noto-jp 에 없다.**
⚠**그런데 물어야 할 것은 기능이 아니라 「표가 흔들리는가」였다** —
**진폭 실측: 넷 다 숫자 10자가 전부 같은 폭이다.** **등폭 코드 서체를 버려도 자릿수는 안 흔들린다.**

### ⚠아직 CI 에서 안 돈다 (의도)

`daily.yml` 은 `npm run build:web` 이 아니라 **`build.ts` 를 직접** 부른다 —
**지금 CI 에서 폰트 단계가 안 돈다.** 받는 화면이 없고 CI 무료 분이 스케줄만으로 88% 차 있어서다.
→ **CSS 배선이 들어가는 변경에서 워크플로에 한 줄을 더한다.**
⚠**비용은 이 기계에서만 쟀다**(부분집합 CPU 약 23초 · 훑기 22.7~154.4초로 **캐시 상태에 따라 7배**).
**§7-5 가 요구한 「CI 로 한 번 돌려 재라」는 아직 안 된 것이다.**

## 6. 단계 — ⚠한 번에 다 바꾸지 않는다

이 사이트는 **매일 자동 배포**되고 화면이 **9,624장**이다.

1. **토큰**(색·간격·활자·괘선 굵기·모션 시간)을 한 곳에 세운다. **화면은 안 바꾼다.**
2. **공통 부품**(상단 크롬 · 탭 · 표 · 툴팁 · 각주)을 토큰 위로 옮긴다.
   ⚠**여기서 `ranking.html` 을 먼저 굽고 실측한다**(§5-1).
3. 화면별 적용 — 홈 → 선수 → 구단 → 순위 → 나머지.
4. 단계마다 **굽고 실기 확인**한다. ⚠이 세션에서 「시험도 타입도 못 잡고 굽고서야 보인」 결함이
   **두 번** 났다(홈 표가 10행 중 7행 투수 · 이적 투수 구단 오배정).

⚠**각 단계는 독립적으로 배포 가능해야 한다.** 절반만 적용된 상태로 며칠 서 있어도
화면이 성립해야 한다.

### 7-2. ⚠막대 연출 — 모순이 실재했고 사용자가 정했다

리뷰가 잡은 것: **「진입 연출까지(막대 차오름)」**(§0-⑵)와 **「표 행·셀에는 트랜지션을 걸지 않는다 ·
모션은 조작층에만 · 표 크기와 무관한 고정 비용」**(§3)이 **동시에 참일 수 없다** —
**막대는 표 안에 있기 때문**이다(감사 §0 이 그렇게 적었다).

**사용자 결정: 「짧은 표에서만 연출」.**

- **연출은 화면이 명시적으로 켠다**(기본은 **꺼짐**). **순위 화면은 켜지 않는다.**
- ⚠**상한을 빌드가 검사한다** — 한 화면의 연출 대상이 상한을 넘으면 **빌드 실패**.
  ⚠**그 상한값은 실측으로 정한다**(홈·구단의 실제 막대 수를 세서). **고른 수를 박지 마라.**
- **대가를 적어 둔다**: 같은 종류의 막대가 **화면마다 다르게 동작한다.** 받아들인 것이다.

### 7-5. 착수를 막지 **않는** 것 (리뷰가 지적했지만 단계로 흡수됨)

- **긴 표의 머리 세로 고정**(§5-2) — **미해결이 맞다.** 순위 화면의 표 처리는 **§6-2 에서 실측한 뒤**

  **§6-2 에서 CI 로 한 번 돌려 시간을 재고**, 예산 안에 안 들어오면 **그때 서체를 줄이거나
  주기를 바꾼다.** ⚠**이 저장소는 CI 분 소진으로 배포가 멈춘 이력이 있다**(CLAUDE.md §6).
