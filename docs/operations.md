# 운용 — 일일 갱신과 감시

## 매일 하는 일

```bash
node scripts/update.ts --contact you@example.com
```

1. **어제** 경기 페이지 아카이브
2. DB 적재 (멱등)
3. 새로 등장한 선수 프로필 아카이브·적재
4. 신선도 보고

소요 약 2분(요청 25건 × 3초 + 적재). 계정·클라우드 없이 로컬에서 돈다.

### ⚠왜 「오늘」이 아니라 「어제」인가

진행 중인 경기를 받으면 **미확정 성적이 `final`로 저장된다**(M9 위반).
그런데 npb.jp 경기 페이지에는 **그 경기 자신의 종료 여부를 가리키는 안정된 표시가 없다** —
헤더의 「試合終了」는 그날 전 경기 목록이라 구별되지 않는다.

감지기를 추측으로 만드는 대신 **구조적으로 안전한 시각**을 쓴다.
자정 이후에 돌리면 어제 경기는 확실히 끝나 있다.

만약 진행 중에 받아버려도 **수집은 멱등이고 내용 해시로 판정하므로** 다음 실행에서
확정판으로 갱신된다. 낡은 값이 몇 시간 보일 뿐 영구 오염은 아니다.

## 감시

```bash
node scripts/freshness.ts data/bb.sqlite 2
```

낡았으면 **종료 코드 1**. 크론이 그대로 실패로 잡는다.

### ⚠주 감시는 제품 화면이다

조사에서 무료 외부 감시 3종이 **전부 시한부**로 판명됐다.

| 수단 | 만료 |
|---|---|
| Cloudflare 헬스체크 | Free 플랜에 **없다** (Pro $20/월) |
| GitHub Actions 스케줄 | **60일 무활동 시 자동 비활성화** |
| healthchecks.io | **1년 무로그인 시 계정 삭제** (ping은 활동으로 안 침) |

그래서 감시를 제품 안에 둔다 — **화면이 데이터 신선도를 표시한다.**
제품의 일부인 감시는 만료되지 않고, 별도 계정도 무료 한도도 쓰지 않는다.

보조로 GitHub Actions가 매 실행마다 수집 요약을 리포에 커밋한다 —
리포 활동이 갱신되어 60일 자동 비활성화를 막는다(자기 문제를 자기가 푼다).

## 쓰기 예산

D1 무료는 **하루 10만 행**에서 **차단**된다(과금이 아니다).

| 작업 | 행 수 | 한도 대비 |
|---|---|---|
| 2026 시즌 전량 적재 | 70,821 | 70.8% |
| 일일 증분(6경기) | 약 700 | 0.7% |

한 시즌은 하루에 들어가고 **두 시즌은 안 들어간다.**
`--from` / `--to` / `--max-writes`로 나눠 넣는다 — 상한에 도달하면 **넘기기 전에 멈추고 재개 날짜를 알린다.**

## 알아둘 것

### 경기 페이지는 경기와 무관하게 매일 바뀐다
8/14 페이지에 8/15 경기 링크가 들어간다(헤더 내비). 그래서 하루 지나 다시 받으면 「신규」로 판정된다.
**파싱 결과는 그대로**이고, 「어제 본 숫자와 다른데?」에 답할 때는 **DB의 `revision`**을 보면 된다.

### 격리는 버그가 아니라 판단 요청이다
`quarantine` 표에 뭔가 쌓이면 원문을 보고 규칙을 늘릴지 정한다.
2026 시즌 전량에서 현재 **0건**이다.

## 화면 생성

```
npm run build:web            # data/bb.sqlite → dist/  (2026 시즌)
BB_CONTACT="..." npm run build:web
```

| 항목 | 실측 (2026 시즌, 630경기 시점) |
|---|---|
| 출력 | 700파일 · 25.8MB · 선수 695명 |
| 집계 시간 | 1.8초 |
| 검색 색인 | `players.json` 48KB |
| D1 읽기 | 배포 때 1회. 요청마다 계산하지 않는다 |

**서버가 없다.** 데이터는 하루 1회만 바뀌므로 정적 파일로 낸다.
낡은 데이터로 생성하면 **종료 코드 1**과 함께 화면 상단에 경고 띠가 나온다.

⚠**`BB_CONTACT`를 설정하지 않으면 삭제·정정 요청 창구가 화면에 나오지 않는다**(L4).
가짜 주소를 넣지 않도록 비워 두면 화면이 「미설정」이라고 말하고, 빌드가 경고한다.
**공개 전 필수**다.

## 아직 안 된 것

- **아카이브·DB의 원격 보관** — 지금은 로컬 `data/`에만 있다. R2 연결은 증분 H
- **자동 실행** — `.github/workflows/daily.yml`이 있지만 리포가 아직 GitHub에 없다
- **경기 진행 중 판정** — 위의 「어제」 규칙으로 우회하고 있다
- **화면 배포** — `dist/`를 만드는 데까지. Cloudflare Pages + Access 연결은 증분 H
