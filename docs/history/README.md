저장소를 **공개**하기 위해서다. `packages/parser/test/fixtures/` 의 **npb.jp 픽스처 20장**이
**페이지 전문**이었고 **19장이 자기 바이트 안에** 「二次利用および無断転載を固く禁じます」와
`<meta name="copyright" content="Nippon Professional Baseball Organization.">` 를 담고 있었다.
트리에서 빼도 **이력에 남으면 공개는 이력째 공개**라 소용이 없다(§2-5 4층 · L6).
같이 지운 것: 개발용 스크래치 `probe-tmp.ts` 와 이력에 남은 **OS 계정명**.

경위: `docs/decisions/2026-09-06-repo-public-and-data-store.md`.

canonical URL·라이선스 링크가 파일 안에 있어 귀속이 파일과 함께 간다. **층이 다르다.**

### 그럼 이 표는 왜 여기 있어도 되나 — **사유가 「사라졌다」가 아니다**

| 실측(2026-09-07) | |
|---|---|
| 이 저장소 | **공개** · **포크 아님** |
| 옛 저장소 · 데이터 저장소 | **둘 다 비공개** · 둘 다 포크 아님 |

옛 해시가 가리키는 객체는 **비공개 저장소 안**에 있고, 이 저장소는 그 저장소의 **포크가 아니라**
객체를 나눠 갖지 않는다. **그래서 이 표는 밖에서는 아무것도 열지 못한다.**

⚠**즉 안전한 이유는 「객체가 없어서」가 아니라 「그 저장소가 비공개여서」다.**
**옛 저장소를 공개로 돌리는 순간 이 표는 그것을 꺼내는 색인이 된다.**
→ `muji-j/bb-app` 과 `muji-j/bb-app-data` 는 **계속 비공개로 둔다.**
⚠**이 표를 지우는 것으로는 못 막는다** — 이미 공개된 사본이 남는다. 막는 것은 **비공개 유지**다.
