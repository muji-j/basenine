# @bb-app/store

스키마·적재·조회. 로컬 개발도 CI 도 Node 24 내장 `node:sqlite` 다(SQLite 1파일 · 배포는 정적 사이트).
SQL 은 **SQLite 한 벌**이다(`datetime()` · `STRICT` · `ON CONFLICT` 같은 SQLite 기능은 쓴다 · 5라운드 재검토 2차 Minor).

⚠~~Cloudflare D1(SQLite) 호환 SQL만 쓴다~~ 는 스택이 정적 생성으로 확정되기 전의 서술이다(2026-09-11 정정 · `src/db.ts` 머리말).
⚠**예외 하나 — 마이그레이션 022 는 `openDb` 가 등록하는 JS 함수 `bb_fetched_at` 을 부른다.** D1 처럼 사용자 정의 함수를 못 쓰는 런타임으로
옮기면 022 를 JS 데이터 마이그레이션으로 옮겨야 한다. 아래 쓰기 예산(`--max-writes` · `D1_DAILY_WRITE_LIMIT`)은 **옮길 때를 대비한
장치로 코드에 남아 있다** — 제약 자체는 지금 운영에 없다.

## 사용법

```bash
# 아카이브 → DB (멱등)
node packages/store/tools/load-archive.ts data/archive data/bb.sqlite

# 쓰기 예산을 나눠 이틀에 걸쳐 넣기
node packages/store/tools/load-archive.ts data/archive data/bb.sqlite --max-writes 90000
node packages/store/tools/load-archive.ts data/archive data/bb.sqlite --from 2026-07-01
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--from` / `--to` | 전체 | 경기일 범위 |
| `--max-writes` | `100000` | 이 행 수에 도달하면 **넘기기 전에** 멈추고 재개 날짜를 알린다 |
| `--skip-events` | off | 타석 이벤트를 건너뛴다(경기별 성적만 적재) |

## 타석 이벤트 — 출처가 둘이다

| 필드 | 출처 |
|---|---|
| `outcome` · `rbi` · `raw_box` | **박스스코어**. 17,351행에서 npb.jp 합계와 대조 완료 |
| `inning` · `outs_before` · `bases` · `pitcher_id` · `raw_pbp` | **playbyplay**의 문맥 |

두 소스는 타자별 타석 수가 **632경기 전건 일치**하므로 시간순으로 짝지을 수 있다.
⚠**수가 어긋나면 짝짓지 않고 격리한다** — 어긋난 채 짝지으면 결과가 엉뚱한 투수에게 붙고,
그건 상대전적이 조용히 틀리는 것을 의미한다. 실측 격리 **0건**.

## 실측 (2026-08-15 · 2026 시즌 전량)

```
성립 632건 · 미성립 31건 · 실패 0건 · 소요 32초

=== 쓰기 예산 (D1 무료 한도 100,000행/일) ===
선수 695 · 경기 663 · 타격 17,351 · 투구 5,213 · 타석 46,899 · 격리 0
합계 70,821행 = 한도의 70.8%
```

**한 시즌은 하루에 들어가고, 두 시즌은 안 들어간다.** 그래서 `--from` / `--to` / `--max-writes`가 있다 —
상한에 도달하면 **넘기기 전에 멈추고 재개 지점을 알린다**(초과하면 D1이 쿼리를 거부하므로 복구가 번거롭다).

재적재 실측: 2회차 후 행 수 동일, `revision > 1`인 경기 **0건** — 재적재만으로는 개정이 오르지 않는다.

### ⚠트랜잭션 없이는 못 쓴다

타석 4만 건을 개별 커밋했더니 적재가 **10분을 넘겼다.** 경기 단위로 묶으니 **32초**가 됐다.
부수 효과가 더 중요하다 — 도중에 죽어도 **절반만 적재된 경기가 남지 않는다.**

## 스키마 원칙

| 원칙 | 이유 |
|---|---|
| 선수는 **NPB 공식 ID**가 정본 | 이름 조인 금지(M10). 동명이인·등록명 변경이 실재한다 |
| 이닝은 **아웃 카운트(정수)** | `6.2`를 부동소수로 누적하면 조용히 어긋난다 |
| `competition`·`status` 컬럼을 **처음부터** | 나중에 붙이면 전 쿼리 재작성이다 |
| 집계 테이블을 두지 않는다 | 전부 원시에서 재계산 가능해야 한다 |
| `STRICT` 테이블 | 타입이 맞지 않으면 **적재 시점에** 막힌다. 실제로 REAL이 정수 컬럼에 들어가는 결함을 여기서 잡았다 |
| 외래키 ON | 존재하지 않는 경기의 성적 행이 생기지 않는다 |

## 격리 (quarantine)

**규칙 밖 값을 버리지 않는다.** 다음을 원문과 함께 남긴다.

| kind | 뜻 |
|---|---|
| `unknownToken` | 해석하지 못한 타석 결과 셀 |
| `abMismatch` / `hitMismatch` | 도출한 타수·안타가 npb.jp 합계와 다르다 |
| `paMismatch` | 분류 합계가 타석 수를 넘는다 = 분류 규칙이 빠졌다 |

격리는 **경기 단위로 교체**한다. 재적재해도 쌓이지 않는다.

⚠**격리가 0이 아니면 그건 버그가 아니라 판단 요청이다.** 원문을 보고 규칙을 늘릴지 정한다.
