# @bb-app/store

스키마·적재·조회. **Cloudflare D1(SQLite) 호환 SQL만** 쓴다.

로컬 개발은 Node 24 내장 `node:sqlite`로 한다. 둘 다 SQLite이므로 **SQL은 한 벌이면 되고**,
그 전제를 지키기 위해 방언을 쓰지 않는다. 덕분에 Cloudflare 계정 없이 전부 만들고 검증할 수 있다.

## 사용법

```bash
# 아카이브 → DB (멱등)
node packages/store/tools/load-archive.ts data/archive data/bb.sqlite
```

## 실측 (2026-08-15 · 2026 시즌 전량)

```
성립 632건 · 미성립 31건 · 실패 0건

=== 쓰기 예산 (D1 무료 한도 100,000행/일) ===
선수 695 · 경기 663 · 타격 17,351 · 투구 5,213 · 격리 0
합계 23,922행 = 한도의 23.9%
```

**시즌 전량이 하루 안에 들어간다.** 조사 단계에서 우려했던 「초기 적재가 한도 초과」는
**타석 단위 로그(증분 F)** 의 이야기였고, 경기별 성적 행에는 해당하지 않았다.

재적재 실측: 2회차 후 행 수 동일, `revision > 1`인 경기 **0건** — 재적재만으로는 개정이 오르지 않는다.

## 스키마 원칙

| 원칙 | 이유 |
|---|---|
| 선수는 **NPB 공식 ID**가 정본 | 이름 조인 금지(M10). 동명이인·등록명 변경이 실재한다 |
| 이닝은 **아웃 카운트(정수)** | `6.2`를 부동소수로 누적하면 조용히 어긋난다 |
| `competition`·`status` 컬럼을 **처음부터** | 나중에 붙이면 전 쿼리 재작성이다 |
| 집계 테이블을 두지 않는다 | 전부 원시에서 재계산 가능해야 한다 |
| `STRICT` 테이블 | 타입이 맞지 않으면 **적재 시점에** 막힌다. 실제로 REAL이 정수 컬럼에 들어가는 결함을 여기서 잡았다 |
| 외래키 ON | 존재하지 않는 경기의 성적 행이 생기지 않는다 |

## 격리 (quarantine)

**규칙 밖 값을 버리지 않는다.** 다음을 원문과 함께 남긴다.

| kind | 뜻 |
|---|---|
| `unknownToken` | 해석하지 못한 타석 결과 셀 |
| `abMismatch` / `hitMismatch` | 도출한 타수·안타가 npb.jp 합계와 다르다 |
| `paMismatch` | 분류 합계가 타석 수를 넘는다 = 분류 규칙이 빠졌다 |

격리는 **경기 단위로 교체**한다. 재적재해도 쌓이지 않는다.

⚠**격리가 0이 아니면 그건 버그가 아니라 판단 요청이다.** 원문을 보고 규칙을 늘릴지 정한다.

## 아직 안 한 것

- **집계·조회 쿼리** — 순위·스플릿(증분 E)
- **D1 배포** — wrangler 설정과 원격 마이그레이션. 스키마는 그대로 쓸 수 있다
- **타석 단위 로그** — `playbyplay.html` 파서가 선행(증분 F)
- **경기구분 판정** — 지금은 전부 `regular`로 넣는다. CS·일본시리즈 구간은 별도 판정이 필요하다
